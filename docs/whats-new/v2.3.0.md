# What's New in v2.3.0

Date: 2026-10-05

## Changes

### [PR #504](https://github.com/humlab-sead/sead_shape_shifter/pull/504) Add security hardening phase 1 containment and env\-var allowlist

The application now refuses requests that try to read files outside the web build or the managed
projects directory, and configuration values such as ${SECRET} in project or preview input no longer
expose environment variables that are not on the approved list. Project names that attempt to
escape the projects root (for example ../../victim or an absolute path) are rejected with a clear
400 error, while normal namespaced names like arbodat:arbodat-copy keep working.

### [PR #509](https://github.com/humlab-sead/sead_shape_shifter/pull/509) Implement SIMS identity allocation phases 1\-3 in the ingester

Change request submissions now resolve all SIMS identities in a single ordered batch and check SIMS
capabilities up front, so unsupported operations stop the submission before any output is written
instead of failing mid-run. Proposed Binding Sets now require manual confirmation before a
submission can finalize.

### [PR #510](https://github.com/humlab-sead/sead_shape_shifter/pull/510) Release dev to main: SIMS identity allocation and sequence public IDs

The SEAD change request ingester now allocates SIMS identities for new records and binds approved
matches to existing SEAD aggregates in a single batched step, blocking any operation SIMS does not
support before data is written; binding sets still require manual confirmation. Configured entities
can also have their public IDs reserved automatically from the target database sequence.

## Upgrade Notes

### [PR #504](https://github.com/humlab-sead/sead_shape_shifter/pull/504)

- ${VAR} substitution in project and data-source configuration is now limited to the approved
variable set. If legitimate project YAML references a variable outside the default list, add its
name to the new RESOLVER_ALLOWED_ENV_VARS setting (comma-separated).
 - Behavior changes for previously accepted inputs: entity types tsv and xls are now rejected as
unsupported at the preview boundary, and project names that resolve outside the projects root now
fail with HTTP 400 (BadRequestError) instead of being joined onto the projects root. Existing
ResourceConflictError/ResourceNotFoundError semantics are unchanged.
 - No migrations or other deployment actions are required by this change.

### [PR #509](https://github.com/humlab-sead/sead_shape_shifter/pull/509)

- Binding Set confirmation is now manual: the ingester no longer confirms proposed Binding Sets, so
workflows that relied on auto-confirmation must confirm sets externally before the submission
proceeds.
 - Callers may pass run_id in the submission context to reuse the SIMS idempotency key across
retries; when absent, a fresh UUID is minted per execution.
 - The dating material entity in resources/target_models/sead_superset_model.yml now uses
material_dated (instead of dating_material_name) as its identity column and unique set; consumers of
that entity's model metadata should update accordingly.

### [PR #510](https://github.com/humlab-sead/sead_shape_shifter/pull/510)

- Entities that should get public IDs from the database must declare public_id_generation:
database_sequence with target_table and public_id set, and an explicit non-tracked
identity_tracking; tracked entities must continue to be allocated by SIMS.
 - The ingester now requires a SIMS capability response and batch resolve support before
orchestrating identity work; plan runs against a SIMS service without these will be blocked by the
preflight.
 - Binding set confirmation is no longer automatic: runs whose binding sets are not confirmed will
report blocked rows until a reviewer confirms them.
 - surrogate_name is no longer part of the entity schema; entity definitions should not rely on it.
 - For local development, copy .env.example to .env and run make development-authorization to
bootstrap the development authorization database.
