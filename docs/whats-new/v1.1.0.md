# What's New in v1.1.0

Date: 2026-01-12

## Changes

### [PR #109](https://github.com/humlab-sead/sead_shape_shifter/pull/109) Add Docker deployment and serve frontend via FastAPI backend

Shape Shifter can now be built and run with Docker (or Docker Compose) as a single container that
serves both the web UI and the API at http://localhost:8012, so the frontend no longer needs a 
separate web server. When no built frontend is present, the backend still runs in API-only mode.

### [PR #128](https://github.com/humlab-sead/sead_shape_shifter/pull/128) Fix data sources, session reuse, and add reconciliation YAML editing

Reconciliation specifications can now be edited either in a form or directly as YAML, and each
specification shows a validation status with hover details so configuration errors are visible
before running reconciliation. Opening a project reuses an existing editing session instead of
creating a new one, data source forms show saved values (such as database and port) correctly, and
the Entity Editor offers form, split, and preview-only layouts.

### [PR #130](https://github.com/humlab-sead/sead_shape_shifter/pull/130) Add "ingestion" capability to Shape Shifter workflow \(\#129\)

Shape Shifter can now ingest data submissions into a SEAD Clearinghouse database: users can select
an ingester on the new "Data Ingestion" page (or via the API or the sead-ingest CLI), validate an
Excel file against the SEAD schema, and then register, upload and explode the submission into the
database.

### [PR #132](https://github.com/humlab-sead/sead_shape_shifter/pull/132) Relocate SEAD ingester to top\-level ingesters/ with dynamic discovery

SEAD ingester data ingestion now works from a standalone ingesters/ directory: ingesters are found
and loaded automatically when the backend, CLI, or tests start, and new ingesters can be dropped
into ingesters/ without touching backend code. Which ingester folders are searched and loaded can be
controlled with the new INGESTER_PATHS and ENABLED_INGESTERS settings.

### [PR #133](https://github.com/humlab-sead/sead_shape_shifter/pull/133) Add Docker deployment, SEAD ingester system, and reconciliation UX

Shape Shifter can now be deployed with a single Docker Compose command, and users can validate and
ingest Excel submissions into the SEAD Clearinghouse directly from the new Data Ingestion screen,
REST API, or sead-ingest command-line tool. The app also includes an in-app user guide with quick
navigation, and reconciliation specifications can now be edited in dual-mode form/YAML views with
per-specification validation status.

## Upgrade Notes

### [PR #109](https://github.com/humlab-sead/sead_shape_shifter/pull/109)

- Deployers must initialize the Docker data directory before first run (make docker-setup or
./docker/setup.sh), then edit docker/data/backend.env (SEAD database settings, CORS origins) and
docker/data/.pgpass (permissions 600) — database passwords are expected in .pgpass, not environment
variables.
 - Frontend variables (VITE_*) are build-time only: changing them requires rebuilding the image, not
just restarting the container.
 - Behavior change for API consumers: when frontend/dist exists, the backend's / route serves the
SPA's index.html instead of the previous JSON message ({"message": ..., "version": ..., "docs":
...}); the JSON root endpoint only remains in API-only mode. API routes under the configured prefix
are unaffected.
 - Runtime data (projects, logs, output, backups, tmp) is bind-mounted from docker/data/ by the
provided compose file; plan persistence accordingly.

### [PR #128](https://github.com/humlab-sead/sead_shape_shifter/pull/128)

Deployers gain a new backend endpoint for saving reconciliation configuration as raw YAML (PUT
/projects/{project_name}/reconciliation/raw) and a service manifest endpoint (GET
/reconciliation/manifest); no migrations or configuration changes are required. Developers using the
Makefile should note that the frontend-clear-vite-cache target was replaced by frontend-clear
(clears both the Vite cache and frontend/dist), and a new br+fr target serves the frontend through
the backend for production-like testing.

### [PR #130](https://github.com/humlab-sead/sead_shape_shifter/pull/130)

- Install/refresh the project (e.g. uv sync / editable install) so the new sead-ingest console
script entry point is registered.
 - The SEAD ingester requires network access to a SEAD PostgreSQL database with the clearing_house
import schema (tables clearinghouse_import_tables/clearinghouse_import_columns and the
staging/explode functions); database host, port, database name and user are supplied per request via
the API/CLI/UI configuration, not new environment settings.
 - Makefile users: the ruff-check-fix target has been renamed to ruff (make lint still runs tidy,
ruff and pylint).

### [PR #132](https://github.com/humlab-sead/sead_shape_shifter/pull/132)

- Breaking import-path change: code that imported backend.app.ingesters.sead (e.g. from
backend.app.ingesters.sead import SeadIngester) must now import from ingesters.sead (e.g. from
ingesters.sead import SeadIngester). SeadIngester is no longer exported from backend.app.ingesters.
 - Ingesters are no longer registered by importing them in backend/app/ingesters/__init__.py; they
are discovered at startup. Custom deployments that relied on manual registration must place
ingesters under a discovered path (default ingesters/) with an ingester.py whose class uses
@Ingesters.register(key="<dir-name>").
 - Optional configuration: set INGESTER_PATHS to change search directories and ENABLED_INGESTERS to
restrict which ingesters load (default loads all discovered).
 - Reinstall in editable mode after pulling: pyproject.toml now packages backend* and ingesters*, so
the workspace root must be on the Python path for discovery to import ingesters.<name>.ingester.

### [PR #133](https://github.com/humlab-sead/sead_shape_shifter/pull/133)

- Breaking (Python imports): Ingester implementations moved from backend/app/ingesters/<name>/ to
the top-level ingesters/<name>/ directory; import paths change from backend.app.ingesters.<name> to
ingesters.<name> (documented in the repository instructions and ingesters/README.md).
 - New optional configuration: INGESTER_PATHS (default ["ingesters"]) and ENABLED_INGESTERS
(default: all discovered) control ingester discovery.
 - Docker deployment: Create docker/data/backend.env, docker/data/frontend.env, and
docker/data/.pgpass from the documented templates before running docker compose -f
docker/docker-compose.yml up -d (app served on port 8012).
 - Packaging: pyproject.toml now packages src*, backend*, and ingesters*, and installs a sead-ingest
console script; reinstall in editable mode to pick this up.
 - Removed tooling: scripts/migrate_reconciliation_v1_to_v2.py has been deleted; the Makefile target
ruff-check-fix is now named ruff.
 - Ignore rules: .gitignore now excludes input/*.xlsx and output/*.xlsx.
