# What's New in v1.17.0

Date: 2026-01-31

## Changes

### [PR #190](https://github.com/humlab-sead/sead_shape_shifter/pull/190) Fix entity state syncing and remove server\-side YAML project caching

Reopening an entity in the editor now always shows the latest saved state, since the editor
refetches the entity from the project file each time it opens and the server no longer serves cached
project data. Project configurations must use public_id instead of the old surrogate_id key, which
is no longer recognized.

### [PR #193](https://github.com/humlab-sead/sead_shape_shifter/pull/193) Add entity materialization and SQL\-like append with column renaming

Users can now freeze ("materialize") a dynamic entity into fixed values from the entity editor —
choosing parquet, CSV, or inline storage — and restore it later ("unmaterialize", with cascade for
dependent entities), which keeps reconciliation data stable. Appending tables now supports renaming
the appended columns (by position or explicit mapping) so sources with different column names can be
combined like a SQL union.

### [PR #194](https://github.com/humlab-sead/sead_shape_shifter/pull/194) Add entity materialization and improve caching mechanisms

You can now "materialize" an entity: its computed data is frozen into a static table (with an option
to unmaterialize and restore the live definition, including dependent entities). The entity editor
always shows the latest saved state when re-opened, fixing the issue where recent changes were not
visible. Append sources can now align columns by position or via an explicit column mapping, and
foreign-key suggestions are disabled by default (enable them in settings).

## Upgrade Notes

### [PR #190](https://github.com/humlab-sead/sead_shape_shifter/pull/190)

- Breaking: The legacy surrogate_id key is no longer supported in project YAML. Rename all
surrogate_id entries to public_id in your project files (see the updated projects/arbodat-test.yml
and projects/strucke_test.yml for reference).
 - Fixed-value entities should list system_id and the public_id column explicitly in columns and
include their values in each row, as demonstrated in the updated sample project files.
 - Docker users: the compose build context now resolves relative to the docker/ directory, and the
docker-build-local and docker-rebuild Make targets were removed; use
docker-build/docker-build-github and compose commands instead.

### [PR #193](https://github.com/humlab-sead/sead_shape_shifter/pull/193)

- Foreign key suggestions in the editor are now disabled by default; set ENABLE_FK_SUGGESTIONS=true
(or enable the new "Enable foreign key suggestions" switch in Settings) to restore the previous
always-on behavior.
 - The backend now writes rotating logs to a logs/ directory (LOGS_DIR, LOG_LEVEL, LOG_FILE_ENABLED,
LOG_ROTATION, LOG_RETENTION, LOG_COMPRESSION settings); no action required, but ensure the
directory is writable.
 - Materialization itself is opt-in and adds only optional YAML fields; projects without
materialized entities are unaffected. Note that SQL entities with check_column_names: false now
raise an error if the query result's column count does not match the configured keys/columns.

### [PR #194](https://github.com/humlab-sead/sead_shape_shifter/pull/194)

- Breaking: Project YAMLs must rename surrogate_id to public_id; the old key is no longer read (no
fallback). Fixed entities' columns lists should explicitly include the system_id and public_id
identity columns, and values rows must match that column layout.
 - New optional environment settings: SHAPE_SHIFTER_LOGS_DIR and SHAPE_SHIFTER_LOG_* (level,
rotation, retention, compression) for logging, and ENABLE_FK_SUGGESTIONS (default off) to re-enable
foreign-key suggestions.
 - Materialization is opt-in per entity; no data migration is required. Existing non-materialized
entities behave as before apart from the identity-column changes above.
