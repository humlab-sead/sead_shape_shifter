# What's New in v1.8.0

Date: 2026-01-16

## Changes

### [PR #164](https://github.com/humlab-sead/sead_shape_shifter/pull/164) Add entity Task List feature and reduce Graph view toolbar clutter

You can now track entity progress with a Task List: mark entities as done or ignored from the graph
node context menu, filter the graph by status (to do, done, ignored, blocked, critical), and see
completion percentage in an overlay on the graph. The Graph view toolbar is also less cluttered,
with layout and display options grouped into dropdowns.

### [PR #165](https://github.com/humlab-sead/sead_shape_shifter/pull/165) Add entity task list and streamline graph view toolbar

You can now track entity progress in the graph view: mark entities as done, ignored, or reset them,
filter the graph by task status, and see a completion percentage for the project. The graph toolbar
is also tidier, with layout and display options grouped into two dropdowns.

## Upgrade Notes

### [PR #164](https://github.com/humlab-sead/sead_shape_shifter/pull/164)

- Docker deployments: The default container user/group changed from 1000:1000 to 1002:33 (still
overridable via the USER_UID/USER_GID environment variables). If you rely on the defaults, verify
file permissions on mounted data/ volumes.
 - .pgpass mount: The PostgreSQL .pgpass bind mount moved from ./data/.pgpass to
./data/.pgpass/.pgpass; deployers must place the file at the new nested path.
 - Project files: The new task_list YAML section is optional; existing projects load unchanged and
task features simply report an uninitialized task list until initialized via the new endpoint or UI.

### [PR #165](https://github.com/humlab-sead/sead_shape_shifter/pull/165)

- Docker deployment defaults changed: USER_UID/USER_GID now default to 1002:33 (instead of
1000:1000) in docker-compose.yml and the Dockerfile, and the .pgpass mount path changed to
./data/.pgpass/.pgpass. Deployers must override these values or adjust host permissions/mounts
accordingly.
 - Project YAML gains an optional task_list section (required_entities, completed, ignored).
Existing projects without it remain valid; use POST /projects/{name}/tasks/initialize to generate
one.
