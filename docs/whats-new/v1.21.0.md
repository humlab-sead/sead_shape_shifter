# What's New in v1.21.0

Date: 2026-02-21

## Changes

### [PR #200](https://github.com/humlab-sead/sead_shape_shifter/pull/200) Handle missing entities, add graph edit menu and materialized styling

Entities in the dependency graph can now be edited directly from the node's right-click menu, and
materialized entities are visually marked with a green double border (with a legend in the graph
panel). The entity editor also opens reliably even when the selected entity is not yet loaded in the
store.

### [PR #205](https://github.com/humlab-sead/sead_shape_shifter/pull/205) Add log viewer overlay with keyboard shortcuts, FAB and command palette

You can now open an application log viewer from any page using the new console button in the
bottom-right corner, the Ctrl/Cmd+Shift+L shortcut, or the "Open Log Viewer" command in the command
palette. Logs can be filtered by type, level, and line count, refreshed automatically, and
downloaded as a text file.

### [PR #206](https://github.com/humlab-sead/sead_shape_shifter/pull/206) Add domain exception hierarchy with structured error responses and tips

When something goes wrong, users now see a clear error message with the error type and practical
troubleshooting tips, plus an optional "Technical Details" section for debugging, instead of a bare
error string.

### [PR #207](https://github.com/humlab-sead/sead_shape_shifter/pull/207) Add extra columns field to FK editor

When editing a foreign key, users can now add "extra columns" — additional columns pulled from the
related entity during a join — by mapping a local name to a remote column in a new expandable
section, with the count of mapped columns shown in the section header.

### [PR #216](https://github.com/humlab-sead/sead_shape_shifter/pull/216) Enhance entity preview to accept unsaved entity configurations

You can now preview an entity while editing it — the live preview in the entity editor reflects your
unsaved changes immediately, without needing to save the entity first.

### [PR #218](https://github.com/humlab-sead/sead_shape_shifter/pull/218) Add entity generation from database tables with UI dialog

You can now create a SQL entity straight from a database table: on a project's Data Sources tab,
click the new "Create Entity from Table" button next to a connected data source, pick a table, and
optionally give the entity a name. The entity is generated with a SELECT * query, the table's
primary keys, and a public id, with a configuration preview shown before you create it.

### [PR #220](https://github.com/humlab-sead/sead_shape_shifter/pull/220) Refactor reconciliation into domain models and entity resolution terms

Reconciliation now presents matched identifiers as "Target ID" instead of "SEAD ID" and manages
reconciliation specifications as an entity resolution catalog, making the workflow read the same way
whether you reconcile against SEAD or another target system. Reconciliation behavior (auto-match,
review thresholds, mark-as-unmatched, progress tracking) is otherwise unchanged.

### [PR #225](https://github.com/humlab-sead/sead_shape_shifter/pull/225) Overhaul validation with pure domain validators and unnest fix

Data validation no longer reports spurious "column not found" errors for columns that are melted
away by an entity's unnest configuration, so validation results for unnested entities are reliable.
Validation can also be run against the full normalized dataset instead of preview samples via the
new use_full_data option on the validation service.

### [PR #227](https://github.com/humlab-sead/sead_shape_shifter/pull/227) Add data validation mode option for sample and complete validation

Users can now choose how data validation runs: a fast "Sample Data" mode that checks preview samples
(up to 1000 rows per entity), or a slower but comprehensive "Complete Data" mode that validates the
full normalized dataset. The selected mode is shown as part of the validation result.

### [PR #241](https://github.com/humlab-sead/sead_shape_shifter/pull/241) Add advanced replacement rules and Replacements editor in entity form

You can now define richer value replacements per column in the entity editor's new Replacements tab
— for example regex matches, contains/starts-with/ends-with, set membership, mappings, and blank-out
with fill options — instead of only simple old-to-new mappings. You can also turn off automatic
header cleanup when loading Excel or CSV files via the new sanitize_header option.

### [PR #242](https://github.com/humlab-sead/sead_shape_shifter/pull/242) Fix lost\-update and ghost\-entity bugs in project state management

Entity changes made in quick succession are no longer silently lost, and recreating a project with
the name of a recently deleted project no longer shows leftover "ghost" entities from the deleted
project.

### [PR #249](https://github.com/humlab-sead/sead_shape_shifter/pull/249) Move projects to folder\-based structure with shapeshifter\.yml

Projects are now stored one per folder (<project>/shapeshifter.yml) and can be organized in nested
subfolders (for example arbodat/arbodat-test), and configs can reference shared Excel/database files
and included configs through portable ${GLOBAL_DATA_DIR} / ${GLOBAL_DATA_SOURCE_DIR} paths instead
of hardcoded locations.

### [PR #261](https://github.com/humlab-sead/sead_shape_shifter/pull/261) Enhance system\_id stability for fixed entities with validation

The fixed value entity editor now shows and keeps the real system_id values, and new rows receive
the next ID above the current maximum, so IDs stay stable when rows are added, deleted, or reordered
and related links no longer break. Invalid system_id values (nulls, duplicates, non-positive or
non-integer IDs) are reported during validation and can be repaired with a single confirmed
auto-fix.

### [PR #270](https://github.com/humlab-sead/sead_shape_shifter/pull/270) feat: first alpha release of Shape Shifter

Shape Shifter's first alpha is now available: users can create transformation projects, define and
preview entities from Excel, CSV, or database sources, apply filters, replacements and links,
reconcile lookup values, and materialize normalized SEAD tables through the web interface.

## Upgrade Notes

### [PR #200](https://github.com/humlab-sead/sead_shape_shifter/pull/200)

Deployers using the Docker Makefile targets should note: GIT_REF now defaults to dev instead of main
(override it explicitly to build from another ref), and the docker-build-tag target has been
removed — use build.sh --git-ref <tag> directly or set GIT_REF when building from a specific tag or
branch. No end-user action is required.

### [PR #206](https://github.com/humlab-sead/sead_shape_shifter/pull/206)

- API error responses for domain errors changed shape: detail is now a structured object
(error_type, error_code, message, tips, recoverable, context) instead of a plain string, and
unexpected server errors also return a structured
  500. API consumers that parsed detail as a string must be updated; legacy string responses remain
only for ProjectServiceError/YamlServiceError and other non-domain exceptions.
 - Several service-level exception classes were removed (ProjectNotFoundError, EntityNotFoundError,
EntityAlreadyExistsError, InvalidProjectError, ProjectConflictError, DependencyServiceError,
service-local QueryExecutionError/QuerySecurityError/SchemaServiceError); import the replacements
from backend.app.exceptions.
 - No database migrations or configuration changes are required. New ErrorAlert props are optional,
so existing usages keep working.

### [PR #220](https://github.com/humlab-sead/sead_shape_shifter/pull/220)

- Project files: mapping entries in project
  *-reconciliation.yml files must rename the sead_id key to target_id; the bundled example and test
project files were migrated in this PR, but externally stored project files are not updated
automatically.
 - API consumers: specification endpoints moved from
/api/v1/projects/{project}/reconciliation/specifications[...] to
/api/v1/projects/{project}/reconciliation/mapping-registry[...], and payloads use the renamed models
with target_id instead of sead_id. Update any direct API integrations accordingly.
 - Docker deployments: the compose file now maps host.docker.internal to the host gateway (Docker
20.10+ on Linux) so the backend can reach a reconciliation service published on the host; no other
operator action is documented in this PR.

### [PR #225](https://github.com/humlab-sead/sead_shape_shifter/pull/225)

No end-user action is required. Code that imported backend.app.validators.data_validators (e.g.
DataValidationService) must be updated: validators now live in src/validators/data_validators.py as
pure static functions returning ValidationIssue, and orchestration moves to
DataValidationOrchestrator with an injected data-fetch strategy. ValidationService's constructor
argument changed from data_validator_factory to data_orchestrator_factory.

### [PR #227](https://github.com/humlab-sead/sead_shape_shifter/pull/227)

- End users: no action required; the default mode remains sample, matching the previous
preview-based behavior.
 - API consumers: the POST /projects/{name}/validate/data endpoint gains an optional validation_mode
query parameter (sample | complete, default sample), and ValidationResult responses now include an
optional validation_mode field. Callers of ValidationService.validate_project_data directly must
replace the removed use_full_data boolean with the new validation_mode argument.

### [PR #249](https://github.com/humlab-sead/sead_shape_shifter/pull/249)

- Breaking layout change: the old flat structure (projects/*.yml) is no longer discovered or
loaded. Move each project's YAML into its own directory as shapeshifter.yml (e.g.
projects/aDNA-pilot/shapeshifter.yml); project names may now include path separators for nested
folders.
 - New settings: GLOBAL_DATA_DIR (default ./shared/shared-data) and GLOBAL_DATA_SOURCE_DIR (default
./shared/data-sources) are added to backend settings and created at startup; override them via
environment variables if shared data lives elsewhere.
 - Project operations act on directories: deleting a project removes its entire directory, and
copying a project copies the whole directory tree.
 - The removed reconciliation_migration utility (v1→v2 reconciliation config migration) is no longer
available; reconciliation configs should already be in v2 format.

### [PR #270](https://github.com/humlab-sead/sead_shape_shifter/pull/270)

This is the first release on main, so no migration is required for new installs. For anyone
following the dev branch: the experimental test-run feature (API endpoints, service, and UI) has
been removed, and sample project files and generated output/ CSVs are no longer tracked in the
repository — keep any needed project YAML/Excel files outside the repo working tree.
