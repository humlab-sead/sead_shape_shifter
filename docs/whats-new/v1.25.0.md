# What's New in v1.25.0

Date: 2026-03-21

## Changes

### [PR #362](https://github.com/humlab-sead/sead_shape_shifter/pull/362) Default lookup\-style FK joins to null\-safe unresolved links

Foreign-key lookup joins that use alternative keys now leave a row's link unresolved (with the row
preserved) when its key value is missing, instead of failing, and missing keys never falsely match
each other. Setting allow_null_keys: false explicitly still enforces the previous strict behavior.

### [PR #371](https://github.com/humlab-sead/sead_shape_shifter/pull/371) Add tiny DSL formula support to extra\_columns

You can now derive new columns in extra_columns with simple formula expressions such as
=concat(first_name, ' ', last_name) or =coalesce(preferred_name, full_name), which work for any
entity type and are evaluated once the referenced columns exist. Strings that must literally start
with = can be written with a doubled == prefix.

### [PR #372](https://github.com/humlab-sead/sead_shape_shifter/pull/372) Improve validation refresh, entity editing, filters, and release notes

Data validation now always shows current results instead of stale cached issues, and validation
messages let you click an entity name to open it directly in the editor. You can also write formula
expressions in extra columns (e.g. =concat(upper(code), '-', trim(name))), choose when entity
filters run (after extract, link, or unnest), and browse user-friendly release notes in the new
What's New section.

## Upgrade Notes

### [PR #362](https://github.com/humlab-sead/sead_shape_shifter/pull/362)

This is a behavioral compatibility change: the YAML shape is unchanged, but for left joins on
non-identity remote keys, omitting allow_null_keys now defaults to lenient null handling (row
preserved, FK unresolved) rather than a hard failure. To keep the previous strict behavior for such
a join, set allow_null_keys: false explicitly in its constraints. All other joins are unaffected.

### [PR #371](https://github.com/humlab-sead/sead_shape_shifter/pull/371)

- Behavior change for existing configurations: extra_columns string values that start with a single
= are now parsed as DSL formulas instead of being stored as string constants. If you have such
literal values, escape them by doubling the leading = (e.g. ==concat(a, b) is stored as =concat(a,
b)).
 - UCanAccess/MS Access SQL entities: result column names now come from JDBC column labels when
available, and alias casing is normalized to the configured casing when auto-detecting columns.
Queries whose aliases previously surfaced under different names may now match the configured names;
no configuration change is required, but verify column names in affected SQL entities.
 - No migrations or other actions are required.

### [PR #372](https://github.com/humlab-sead/sead_shape_shifter/pull/372)

- Lookup-style left foreign keys that resolve remote identities from alternative keys now keep rows
with missing key parts unresolved by default when allow_null_keys is omitted (previously this
raised by default). Set allow_null_keys: false explicitly to restore strict errors, or true to
tolerate missing keys.
 - New validation rejects non-fixed entities that list the derived system_id column in columns;
remove such entries from project YAML before upgrading.
 - The CLI entry point src/survey2excel.py is renamed to src/shapeshift.py; update any scripts or
docs that invoke the old path.
 - Existing filters without a stage keep their legacy after-extract timing; no migration is
required.
 - Playwright end-to-end specs are currently disabled (marked skipped) and retained for future
re-enablement.
