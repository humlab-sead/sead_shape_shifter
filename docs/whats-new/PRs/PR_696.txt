## Summary

Fixes four issues and applies related troubleshooter UX improvements.

Row-count troubleshooter UX: The join note moved into the "Inspect results" tooltip; "Rows per page"
now sits beside the Unmatched / Multiple matches buttons, which are styled as tabs; an "All"
page-size option was added; the pager only renders when more than one page exists; and the grid
loading overlay is reserved for selections with no rows yet shown. LINK_TROUBLESHOOT_BROWSE_ROW_CAP
and the exception-row page limit rose from 10,000/500 to 25,000 so one request can read every
retained row.

Data-validation check selection (#692): The options form now always sends the exact check selection,
and the API gained an optional validators query parameter (omitted = all selectable checks, empty =
none, unknown name = 422). The orchestrator gates column_exists, natural_key_uniqueness, and
non_empty_result; foreign-key and key-production checks always run. The UI label "Non-Empty Result"
became "Warn on Empty Results".

Integrity troubleshooter context store: Bounded value/row paging was replaced by a server-side,
owner-scoped context store (IntegrityTroubleshooterContextStore, 15-minute TTL with periodic sweep)
that retains the full inspection snapshot, so each read returns every unmatched value and every
local row of a selected value without re-normalizing. New routes: POST
…/integrity-troubleshooter/{context_id}/page and DELETE …/integrity-troubleshooter/{context_id}; the
request fields page, row_offset, and row_limit were removed. The body gained an "Export unmatched
keys" CSV button using new shared formatCsvCell, toCsv, and downloadCsv helpers, one CSV column per
key part.

Stale-context reporting (#694): Every non-found context lookup now returns the recoverable HTTP 410 
stale-context response instead of falling through to a 404, so swept or unknown identifiers produce
the same reopen prompt as expired ones. The frontend integrity body transparently reopens the
inspection once when its context expires.

Container build: ARGs are scoped to the stages that use them, pnpm and uv cache mounts were added,
and release-identity labels moved to the end of the final stage so identity changes do not
invalidate package layers.

Docs were updated accordingly (operations table, user guide, authorization route inventory), and
proposal records were reorganized (FOREIGN_KEY_LINK_TROUBLESHOOTER_EXPERIMENTS moved to done,
BRANCH_SCOPED_CONSUMERS_FOR_MIXED_BRANCH_PARENTS moved to future).

## User-facing release note

The row-count troubleshooter now offers an "All" page-size option, a 25,000-row browse cap, and
tab-style affected-row categories, and the integrity troubleshooter can export all unmatched keys to
CSV. Data-validation runs now honour which checks are selected, and a stale troubleshooter context
shows a reopen prompt instead of a "Resource not found" error.

## Upgrade notes

 - The default SHAPE_SHIFTER_LINK_TROUBLESHOOT_BROWSE_ROW_CAP changed from 10,000 to 25,000 (maximum
allowed value also 25,000). Operators who set this variable explicitly should verify the value
still suits their environment.
 - The integrity troubleshooter API contract changed: the page, row_offset, and row_limit request
fields were removed, and clients must use the new context-based flow via POST
…/integrity-troubleshooter/{context_id}/page and DELETE …/integrity-troubleshooter/{context_id}.
 - Context routes that previously returned 404 for unknown identifiers now return HTTP 410 with a
recoverable stale-context detail; API consumers keying on that status should account for it.
