## User-facing release note

Application errors now return generic messages without exposing internal details, and server logs
redact credentials. Deployments can run as a rootless Podman container reachable only through an
authenticating nginx reverse proxy.

## Upgrade notes

 - The container/ directory replaces the Docker path as the supported deployment: build with make
build (or make build-local), configure container-data/backend.env (mode 600), and keep PostgreSQL
passwords in container-data/.pgpass/.pgpass, not in backend.env.
 - Production mode requires SHAPE_SHIFTER_TRUSTED_PROXY_AUTH_ENABLED=true and a non-empty
SHAPE_SHIFTER_AUTHORIZATION_BOOTSTRAP_ADMIN_PRINCIPALS; the reverse proxy must send the
authenticated user in X-Authenticated-User (see
container/scripts/deploy/nginx-shape-shifter.conf.template), otherwise the API returns 401.
 - The published port is bound to 127.0.0.1 only; external access must go through nginx. Images
previously built from dev still publish on all interfaces and must be rebuilt from this branch.
 - Clients depending on the projects_dir field in /api/v1/health must stop reading it; the field was
removed.
 - sqlparse is now a core dependency; uv sync picks it up automatically.
