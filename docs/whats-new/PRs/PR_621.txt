title: Add target-model guided entity creation, verify auth route metadata
description:
## Summary

Two related changes are included in this PR:

Authorization route inventory maintenance. Endpoints that were classified only in
AUTHORIZATION_ROUTE_INVENTORY.md now carry their classification in code: new
declare_authenticated_route / declare_public_route decorators in
backend/app/authorization/dependencies.py attach authorization_requirement metadata to endpoints
without adding a runtime check, and are applied to the metadata, log, suggestion, schema,
reconciliation, help-docs, what's-new, and other authenticated routes (the health check is marked
public; generated docs routes are marked in main.py). require_project metadata now records a
condition (key=sead_change_request) for the conditional Change Request check. The route tests drop
the hand-maintained path sets and add test_route_inventory_matches_authorization_metadata, which
compares each inventory requirement label with the assembled endpoint/dependency metadata; the
UNDECLARED and enforcement pending concepts and the dated classification review are removed.
Lifecycle and background-task coverage moved from the inventory into AUTHORIZATION.md as a new
"Resource Lifecycle And Background Operations" section.

Target-model guided entity creation (Phases 1–3). New read-only backend support:
TargetModelEntityOptionsService projects a project's associated target model into missing-entity
options (name, role, required flag, description, target table, public ID, required non-generated
columns, and required links with direct/via paths, missing path entities, and conditional
required_when_has_new_rows triggers), exposed via GET /api/v1/projects/{name}/target-model-entities
behind project:read. Absent models return configured: false; configured-but-missing/invalid models
return HTTP 400 without exposing paths or parser text; GET never writes project YAML. On the
frontend, EntityFormDialog create mode gains a "Start from target model" picker that prefills and
locks the entity name and public ID (with confirmation before replacing edited values), requires an
explicit source type (classifiers restricted to fixed/sql), shows target requirements as read-only
reference data that never enter the save payload, and refreshes candidates when create mode reopens
after a save. The proposal and phase plans moved to docs/proposals/done/ with completed task
checkboxes and recorded execution results.

## User-facing release note

When adding an entity to a project with an associated target model, users can now pick a missing
target-model entity in the "Start from target model" picker: the entity name and public ID are
prefilled, the target's required columns and links (including conditional links) are shown as
reference information, and the entity is saved only through the normal create action. Manual entity
creation remains fully usable when no target model is configured or the options request fails.
