title: Enforce safe SQL execution and database boundaries
description:
## Summary

This PR implements Phase 3 of the security-hardening plan: a single read-only SQL policy is now
enforced on every SQL and DuckDB execution path, query results are bounded by server-owned limits,
and database access is moved to least-privilege principles.

 - Shared SQL safety policy (src/sql_policy.py, documented in docs/SQL_SAFETY_POLICY.md):
validate_read_only_sql() / ensure_read_only_sql() allow exactly one executable SELECT statement and
fail closed on stacked statements, DDL/DML (including writes nested in CTEs), file/extension
operations (COPY, ATTACH, INSTALL, LOAD, EXPORT, IMPORT), and transaction/session/administrative
operations (SET, CALL, PRAGMA, VACUUM, etc.). The policy is applied in QueryService (validation,
execution, and column introspection, before any loader is created), in SqlLoader and its SQLite,
PostgreSQL, and UCanAccess implementations before read_sql()/execute_scalar_sql(), in DuckDbLoader,
and in DuckDbWorkspace.execute()/query_df()/query_scalar()/explain().
 - Query construction hardening: identifier quoting now escapes embedded quotes and rejects empty or
NUL-containing identifiers; PostgreSQL, SQLite, and UCanAccess metadata/introspection queries pass
filter values as bound parameters instead of f-string interpolation; schema_service builds its
table-import query via loader quote_name/qualify_name.
 - Server-owned result limits: inject_limit() caps user LIMIT clauses at 10,000 rows (preserving
lower user limits, nested limits, and OFFSET), direct table loads are capped, and the backend query
service adds a 5 MiB serialized-response budget, a configurable per-query memory limit
(memory_limit_mb, default 64 MiB), a shared concurrency semaphore (4), and timeout/cancellation
handling that releases the concurrency slot. The public execute-query route forwards limit, timeout,
and memory_limit_mb.
 - DuckDB restrictions: the internal workspace is now strictly transient (:memory: only; persistent
paths are rejected), external access, unsigned/community extensions, and extension autoloading are
disabled at runtime, and regex guards reject file-read functions and network URLs in workspace
queries.
 - PostgreSQL least privilege: new scripts/postgres/ setup, grant-verification, and role-behavior
test scripts create and verify a dedicated read-only application role; docs/OPERATIONS.md documents
the procedure.
 - Error hygiene: API and service errors no longer echo raw SQL, backend error text, or connection
details; clients receive stable messages (e.g. "Query rejected by the SQL safety policy."). sqlparse
moved from the api extra to core dependencies. Phase 3 task-plan and validation documents are added
under docs/proposals/MITIGATE_SECURITY_ISSUES/done/.

## User-facing release note

SQL queries run through Shape Shifter are now strictly read-only: stacked statements, destructive or
administrative SQL, and DuckDB file/network access are rejected before execution, and query results
are capped by row count, response size, and memory limits. Query errors no longer expose raw SQL or
backend details, so clients see stable, safe error messages.

## Upgrade notes

 - Query API behavior changes: multiple statements now fail validation (previously only warned), and
only read-only SELECT statements execute on all covered paths. Any workflow relying on
multi-statement or non-SELECT SQL through these paths will be rejected.
 - The query execute request accepts a new optional memory_limit_mb field (1–1024, default 64);
results exceeding the memory limit or the 5 MiB serialized-response budget are rejected or
truncated.
 - sqlparse is now a core dependency (previously only in the api extra); no other dependency
changes.
 - Deployers of PostgreSQL-backed data sources should create a dedicated read-only application role
with scripts/postgres/create-readonly-role.sh and verify it with verify_readonly_role.sql /
test-readonly-role.sh, as documented in docs/OPERATIONS.md.
 - Any use of DuckDbWorkspace with a persistent database path now raises; the workspace is in-memory
only.
