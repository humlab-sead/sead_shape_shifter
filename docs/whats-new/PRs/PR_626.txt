title: Enhance cached value reference UX in entity forms
description:
## Summary

Implements Phases 1–2 of the VALUE_REFERENCE_COLUMN_UX_ENHANCEMENT proposal so @value:
entities.<entity>.keys/columns references are usable in the entity form:

 - Completed-cache gate (frontend/src/stores/entity.ts): new getCompletedEntitiesFor(projectName)
returns entities only when a successful, current list load owns the cache ([] is valid, null means
unavailable). A request-generation counter prevents stale or out-of-order responses from restoring
ownership; syncCachedEntity now takes the project name, and same-project mutations retain ownership
while cross-project ones invalidate it.
 - Pure expansion helper (frontend/src/utils/valueReferenceColumns.ts, new): expandValueReference()
expands complete scalar/mixed/nested references in Core order with duplicates retained and returns
null (never partial columns) for missing paths, cycles, or unsupported values;
getValueReferenceSuggestions() lists only fully supported references from the cache.
 - Picker suggestions and preview: EntityFormDialog.vue, ForeignKeyEditor.vue, and UnnestEditor.vue
append cache-derived reference choices to the ordinary candidates in Business Keys, non-fixed
Columns, FK Local/Remote Keys, unnest ID/Value Variables, Deduplication Columns, and Drop Empty
Rows. The new ValueReferenceChip.vue renders selected @value: chips with an explicit, read-only
preview ("Based on cached configuration", "Preview unavailable", or an empty-result message) that
never edits the model or triggers validation. FK Local/Remote key suggestions no longer mix in
backend getValidDirectives() results or column-extracted directives; directive loading remains only
for the extra-column source, and existing key edit validation is unchanged.
 - Raw-shape preservation: the dialog captures each supported field's raw scalar/list form on load
or valid YAML apply and restores it on save when the field is semantically unchanged, so untouched
references, mixed lists, and legacy + expressions round-trip exactly.
 - ValidationPanel UX: the "Data Validation Execution" card moves into a dedicated Execution tab
that falls back to All Issues when execution data disappears.
 - Backend refactor: EntityConfigMapper.to_core() now receives a keyword-only entity_name instead of
callers injecting/popping a name key in the config; shapeshift_service drops its local
FixedEntityShapeValidationError mapping (the fixed mapper raises domain errors with the entity name
directly), and the fixed-entity shape error tip was reworded.
 - Docs: Phase 1 task plan is marked complete with execution results; a new Phase 2 task plan
records scope, validation, and completion.

## User-facing release note

In the entity form, column pickers now suggest complete @value references from the project's cached
entities, and a preview button on a reference chip shows the exact columns it expands to without
changing your configuration; saving an entity leaves untouched reference values exactly as they were
written.
