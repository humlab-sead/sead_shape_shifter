## Summary

Adds the ability to upload Excel/CSV files for use in data source configurations (issue #174).

 - Backend: New endpoints GET /api/v1/data-sources/files (list, with optional ext filter) and POST
/api/v1/data-sources/files (multipart upload) backed by new ProjectService methods. Uploads are
stored in a new global data source files directory (DATA_SOURCE_FILES_DIR, default ./input,
auto-created on startup). Saves enforce allowed extensions (.xlsx, .xls, .csv), a 50 MB size cap,
filename sanitization, and automatic renaming on filename collision. A new ProjectFileInfo model
reports name, server-relative path, size, and last-modified time (ISO 8601). The service also gains
per-project uploads/ directory helpers (list_project_files, save_project_file).
 - Frontend: New dataSourceFilesApi (data-source-files.ts) and project file list/upload client
methods. DataSourceFormDialog now renders file_path driver fields with a Select/Upload toggle: users
can pick an existing file from the data source files directory or upload a new one, with per-driver
extension filtering (csv/tsv, mdb/accdb, xlsx/xls). The driver select deduplicates alias drivers
(e.g. csv/tsv, xlsx/openpyxl) by display name, with a new getCanonicalDriver helper used when
editing existing sources.
 - Supporting changes: Settings.VERSION now reads __version__ from backend/app/__init__.py, and
semantic-release updates/bumps that file on release. backend/app/scripts/config.yml gains
table_name_overrides and table_name_ignores entries. The docker Makefile replaces sudo invocations
with guard-user/guard-cwd checks requiring the sead user (or root) and the deploy directory.
docs/images/README.md documents Mermaid diagram extraction/SVG generation targets. Minor UI tweaks:
closable SessionIndicator alert and simplified layout in ProjectDetailView.

## User-facing release note

Users can now upload Excel (.xlsx/.xls) or CSV files directly from the data source form, or select a
previously uploaded file from a dropdown, so data source paths no longer have to be typed or placed
on the server by hand. The data source type dropdown also no longer shows duplicate driver entries.

## Upgrade notes

 - A new DATA_SOURCE_FILES_DIR setting (env SHAPE_SHIFTER_DATA_SOURCE_FILES_DIR, default ./input)
controls where uploaded data source files are stored; deployers should point it at a persistent,
writable location. The directory is created automatically on startup.
 - Release automation now also writes the version into backend/app/__init__.py (in addition to
pyproject.toml); the app's reported version comes from that file. No manual migration is otherwise
required.
