title: Title: fix(auth): use body source locator for project connections
description:
## Summary

Fixes a parameter collision in the shared data-source authorization dependency that caused POST
/projects/{name}/data-sources to return 404 Resource not found when connecting a data source to a
project. Previously, require_shared_data_source resolved the locator from route parameters (filename
or name or data_source_name) before reading source_filename from the request body, so on the
project connection route it treated the project path parameter (e.g. Roger-test) as the
shared-source locator and looked up the wrong resource.

The dependency now accepts an explicit body_locator keyword that makes it read source_filename from
the request body instead of route parameters, and the project endpoints' shared-source reader
dependency is configured with body_locator=True. Other routes retain their existing path-parameter
lookup. The PR adds regression tests covering route-parameter behavior, body-locator behavior, and
the actual project connection route dependency, and adds an investigation findings document
(docs/investigations/connect-sead-data-source-404/findings.md) documenting the root-cause analysis.
Generated graph artifacts under graphify-out/ were also updated.

## User-facing release note

Users can now connect a SEAD (or other shared) data source to a project using the CONNECT action
without the request failing with a "Resource not found" error, even when the project name differs
from the selected source name.
