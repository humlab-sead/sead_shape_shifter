title: fix(auth): authorize project data-source connections from body source
description:
## Summary

The shared data-source authorization dependency previously resolved its locator from route
parameters (filename, name, or data_source_name) before ever reading source_filename from the
request body. On POST /projects/{name}/data-sources, FastAPI bound the project path parameter to the
dependency's name argument, so the permission check looked up the project name as a shared data
source and returned a concealed 404 Resource not found — this is the reported failure when pressing
CONNECT on a new project (Refs #587).

require_shared_data_source now accepts a body_locator option that makes the dependency authorize the
body's source_filename instead of any route parameter. The project connection route is configured
with body_locator=True; all other routes keep their existing path-parameter lookup. Regression tests
cover the body-locator route (a project name parameter must not override an authorized body source)
and the default path-parameter behavior. The PR also adds
docs/investigations/connect-sead-data-source-404/findings.md documenting the investigation and root
cause.

## User-facing release note

Connecting a shared data source (such as SEAD) to a project from the Connect dialog no longer fails
with a 404 "Resource not found" error for users who have access to the project and the selected
source.
