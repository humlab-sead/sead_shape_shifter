# What's New in v2.2.0

Date: 2026-09-23

## Changes

### [PR #485](https://github.com/humlab-sead/sead_shape_shifter/pull/485) Add authentication, authorization, and Podman deployment to dev

Shape Shifter now requires users to sign in through the reverse proxy: unauthenticated requests to
the API are rejected, and each user only sees and edits the projects and data sources they have been
granted access to. Database queries run read-only with enforced result limits, so accidental data
modification through the editor is no longer possible.

### [PR #487](https://github.com/humlab-sead/sead_shape_shifter/pull/487) docs: consolidate documentation and retire docker path

Project documentation now has a single clear front door: the README, user guide, operations guide,
and diagrams all describe the supported Podman deployment, with a quick start (make setup, make
build, make up, make healthcheck) and links to the guide that owns each topic. Docker-based
deployment instructions have been removed.

### [PR #495](https://github.com/humlab-sead/sead_shape_shifter/pull/495) Add centralized authorization system cutover

Project and shared-data-source access is now centrally managed and enforced: users see and can work
with only the projects they have been granted, and projects they cannot access are concealed rather
than merely refused. Operators can change who can access what by reviewing and applying an
authorization manifest, without redeploying the application.

### [PR #499](https://github.com/humlab-sead/sead_shape_shifter/pull/499) Document host gateway requirement for container access to host services

The deployment guide now explains that the container must reach services running on its host through
host.docker.internal rather than the host's LAN address, and why a successful host-side connection
check does not prove the container can connect.

### [PR #500](https://github.com/humlab-sead/sead_shape_shifter/pull/500) Re\-scope Phase 4 to a UAT\-ready deployment and correct the access probe

The authenticated access check now reports each tested principal's deployment roles and marks a
privileged read as expected instead of reporting a false isolation failure, and the record states
how many isolation directions were actually verified. A UAT-ready deployment record documents how to
exercise the authorization-enabled test deployment.

## Upgrade Notes

### [PR #485](https://github.com/humlab-sead/sead_shape_shifter/pull/485)

- Production startup now fails unless SHAPE_SHIFTER_TRUSTED_PROXY_AUTH_ENABLED=true and
SHAPE_SHIFTER_AUTHORIZATION_BOOTSTRAP_ADMIN_PRINCIPALS lists at least one administrator; a reverse
proxy (nginx template provided) must forward the authenticated identity in X-Authenticated-User,
otherwise the API returns 401.
 - A new SQLite authorization database (AUTHORIZATION_DATABASE_PATH, default
state/authorization.sqlite3) must be created and persisted across rebuilds; the sead-authorization
CLI manages it. Existing projects have no grants until resources are registered and access is
assigned.
 - CORS no longer allows devtunnel/GitHub-preview wildcard origins; remote frontends must be listed
explicitly in ALLOWED_ORIGINS.
 - Data source configurations with custom connection strings or environment variables outside the
approved prefixes (SEAD_, SHAPE_SHIFTER_) are now rejected.
 - Database access is read-only: create a restricted PostgreSQL role with the new
scripts/postgres/create-readonly-role.sh and point data sources at it.
 - Deployers must rebuild the container image from this branch to activate the loopback-only
published port and trusted-proxy authentication; the previously built image still publishes the
backend on all interfaces with no identity enforcement.
 - sqlparse is now a core (non-API) dependency; reinstall dependencies after pulling.

### [PR #487](https://github.com/humlab-sead/sead_shape_shifter/pull/487)

Operators using the retired docker/ path must move to the supported Podman deployment in container/:
the docker/ directory and the root Makefile Docker targets (docker-build, docker-up,
docker-restart, docker-patch-frontend, and friends) are deleted. Follow container/README.md for
setup, configuration, and lifecycle commands, and container/DEPLOYMENT.md for hosts, NGINX, systemd,
and multiple environments. The documented first-start sequence is make setup && make build && make
up && make healthcheck, with persistent data under ../container-data (DATA_DIR). No application
configuration or data migrations are introduced by this PR.

### [PR #495](https://github.com/humlab-sead/sead_shape_shifter/pull/495)

Deployers must migrate to the new target layout before or during this cutover:

 - Configuration moves out of the data directory: deployment.env, backend.env, and .pgpass now live
in ~/config (created by make setup); mutable data stays in ~/container-data and code in ~/container.
 - The authorization SQLite database must be initialized and an authorization manifest applied;
container/scripts/deploy/bootstrap-authentication-and-authorization.sh and the sead-authorization
CLI provide the migration, apply, reconcile, backup, and restore steps.
container/resources/authorization.env.example documents the new authorization environment settings.
 - The systemd user service now starts the stack with --no-build; use
container/scripts/deploy/rebuild-image.sh when an image rebuild is needed.
 - API consumers: project metadata updates no longer rename a project; the name field in the update
request is ignored.

### [PR #499](https://github.com/humlab-sead/sead_shape_shifter/pull/499)

No action is required to adopt this documentation change itself. For deployments where a host
service (for example PostgreSQL) runs on the container host, the newly documented requirement
applies: point container configuration at host.docker.internal (e.g. SEAD_HOST=host.docker.internal)
and add a matching .pgpass entry keyed to that host string, since .pgpass matches the host exactly
as used.

### [PR #500](https://github.com/humlab-sead/sead_shape_shifter/pull/500)

No configuration or migration changes ship with this PR. The corrected probe script reaches the
deployment host only after this lands on dev and the synced ~/container tree is refreshed via
container/scripts/deploy/sync-to-deploy; the record notes the target still runs the old script until
then.
