# What's New in v1.12.0

Date: 2026-01-20

## Changes

### [PR #175](https://github.com/humlab-sead/sead_shape_shifter/pull/175) Add Excel/CSV upload and file picker for data source configuration

Users can now upload Excel (.xlsx/.xls) or CSV files directly from the data source form, or select a
previously uploaded file from a dropdown, so data source paths no longer have to be typed or placed
on the server by hand. The data source type dropdown also no longer shows duplicate driver entries.

### [PR #176](https://github.com/humlab-sead/sead_shape_shifter/pull/176) Add Excel/CSV file upload to data source directory

When configuring a data source that reads a file, you can now upload an Excel or CSV file directly
from the form or pick one you uploaded earlier, instead of typing a server path by hand. Uploaded
files are kept in the workspace input folder and are available to all data source configurations.

## Upgrade Notes

### [PR #175](https://github.com/humlab-sead/sead_shape_shifter/pull/175)

- A new DATA_SOURCE_FILES_DIR setting (env SHAPE_SHIFTER_DATA_SOURCE_FILES_DIR, default ./input)
controls where uploaded data source files are stored; deployers should point it at a persistent,
writable location. The directory is created automatically on startup.
 - Release automation now also writes the version into backend/app/__init__.py (in addition to
pyproject.toml); the app's reported version comes from that file. No manual migration is otherwise
required.

### [PR #176](https://github.com/humlab-sead/sead_shape_shifter/pull/176)

- A new DATA_SOURCE_FILES_DIR setting (default ./input, created automatically on startup) holds
uploaded data source files; deployers may point it elsewhere via configuration.
 - Uploads are limited to .xlsx, .xls, and .csv files up to 50 MB; other types are rejected.
 - Docker deployment targets (docker-build, docker-build-local, docker-build-tag,
update-deploy-scripts, etc.) must now be run as user sead (or root) from the deploy directory, and
no longer invoke sudo.
