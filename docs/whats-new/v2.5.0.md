# What's New in v2.5.0

Date: 2026-11-11

## Changes

### Link Troubleshooter

A new read-only **Link Troubleshooter** lets you investigate foreign-key warnings directly from the validation panel. Clicking "Troubleshoot link" on a supported warning opens a responsive workspace that:

- Leads with a plain-language summary stating how many source rows have no match and what the configured join does with them, with saved-link details condensed to a single line and null-key options explained in tooltips.
- Shows the correct entity pair (e.g. "orders → customers") immediately on open.
- Lets you reproduce the warning, compare alternative join key pairs, and see which rows failed to match or matched multiple rows—all without changing the project.
- Keeps a 15-minute snapshot of the reproduced link; opening or refreshing after expiry reads current data, while changing exception group, side, page, or page size reads nothing new. Run trial, Reset, and Close are explicit actions; Reset restores the latest baseline without recomputing.
- Arranges settings and results side by side on wide screens, with row inspection reachable in one click. After running a trial, changing settings keeps the previous comparison visible and clearly marks it as stale until rerun.
- Shows one result at a time with "Saved link" and "Last trial" toggle buttons, count cards for source and output row totals, and a delta against the configured link when viewing trial results.
- Pages affected-row lists up to 25,000 rows (with an "All" page-size option and tab-style categories), shows a message when a result set exceeds the browsable window, and supports CSV export of all unmatched keys from the integrity troubleshooter.
- Supports dialog resizing by drag or arrow keys; integrity counts appear as stat cards with explanatory tooltips.
- Displays a reopen prompt for stale contexts instead of a "Resource not found" error.

The **Foreign-Key Integrity Troubleshooter** additionally shows the current unmatched values behind a warning, how many local rows each value affects, and a bounded sample of local rows for a selected value. Warnings that cannot be inspected (e.g. older warnings without saved-link identity) explain why instead of offering the action.

Data validation now runs in **complete mode by default**, so foreign-key warnings are checked against full data instead of a 1,000-row sample. Link troubleshooting is unavailable for sample results, with guidance to re-run complete validation. Troubleshooter dialogs open on unmatched rows and no longer show a success banner when the warning reproduces as expected.

*(PRs [#645](https://github.com/humlab-sead/sead_shape_shifter/pull/645), [#660](https://github.com/humlab-sead/sead_shape_shifter/pull/660), [#674](https://github.com/humlab-sead/sead_shape_shifter/pull/674), [#676](https://github.com/humlab-sead/sead_shape_shifter/pull/676), [#678](https://github.com/humlab-sead/sead_shape_shifter/pull/678), [#683](https://github.com/humlab-sead/sead_shape_shifter/pull/683), [#685](https://github.com/humlab-sead/sead_shape_shifter/pull/685), [#687](https://github.com/humlab-sead/sead_shape_shifter/pull/687), [#689](https://github.com/humlab-sead/sead_shape_shifter/pull/689), [#696](https://github.com/humlab-sead/sead_shape_shifter/pull/696))*

### Reconciliation: Keyed Decisions, Manifest-Driven Types, and SIMS Contracts

Reconciliation now requires **explicit operator review**: candidate search proposes matches keyed by business key, and only accepted decisions whose SEAD target is verified at export time become applied links. Rows marked local-only allocate a new ID only for entities using reconcile-exact or reconcile-fuzzy mode; all other unresolved rows are blocked rather than silently matched.

Reconciliation types and their properties are now read from the **reconciliation service manifest**, so a new entity type can be configured without a Shape Shifter code change. Saved specifications that use a type or property the service no longer declares stay visible but are clearly marked unsupported and blocked from candidate matching until removed or remapped.

Change Request runs now **confirm the project's business-key declarations with SIMS** before sending identity work; a conflicting key list stops the run with a readable conflict message instead of silently mismatching identities. Project saves no longer block key edits on bound projects. The reconciliation review grid scrolls large result sets faster, preview rows load only when the review tab is opened, and the editor uses clearer "Search Field" and "Another Entity" terminology.

*(PRs [#634](https://github.com/humlab-sead/sead_shape_shifter/pull/634), [#668](https://github.com/humlab-sead/sead_shape_shifter/pull/668), [#672](https://github.com/humlab-sead/sead_shape_shifter/pull/672))*

### Entity Editor & Target Model

- **Target-model guided entity creation**: When adding an entity to a project with an associated target model, users can pick a missing target-model entity in the "Start from target model" picker. The entity name and public ID are prefilled, the target's required columns and links (including conditional links) are shown as reference information, and the entity is saved only through the normal create action. Manual entity creation remains fully usable when no target model is configured or the options request fails. *(PR [#621](https://github.com/humlab-sead/sead_shape_shifter/pull/621))*

- **Direct target-ID foreign key selector**: Project authors can select direct target model IDs in the entity editor's Basic tab instead of editing YAML by hand. Selecting or clearing a target updates only that value source; existing `system_id` and stale entries are preserved, and validation offers a shortcut to column settings when a required ID column is missing. *(PR [#702](https://github.com/humlab-sead/sead_shape_shifter/pull/702))*

- **Conditional direct-ID FK validation**: Conditional direct-ID foreign keys no longer trigger reconciliation for valid declarations, improving efficiency in data handling. *(PR [#706](https://github.com/humlab-sead/sead_shape_shifter/pull/706))*

### New DSL Functions

- **`map_value`**: Maps exact input values to typed literals (e.g. `'artificial' → 1`, `'natural' → 2`), with an optional fallback for unmapped values. Null inputs pass through unchanged. *(PR [#699](https://github.com/humlab-sead/sead_shape_shifter/pull/699))*
- **`split_part`, `concat_ws`, `regex_replace`, named capture groups**: Formula expressions can now split delimited strings by index, join optional parts while skipping nulls, perform regex-based replacement, and extract named capture groups—replacing hand-built prefix regexes and deeply nested `replace`/`coalesce` chains. *(PR [#701](https://github.com/humlab-sead/sead_shape_shifter/pull/701))*

### Entity Form: Cached Value Reference UX

Column pickers now suggest supported `@value` references from the loaded project cache, and a preview button on a reference chip shows the exact columns it expands to, based on cached configuration, without changing your selection or saved YAML. Reference values you did not edit are saved back exactly as they were loaded. *(PR [#626](https://github.com/humlab-sead/sead_shape_shifter/pull/626))*

### Validation, Caching & Layout Fixes

- Preview and validation results are no longer reused from the wrong project or from a partial run, and an entity that fails during normalization no longer appears with half-built data. Previously mis-cached results are recomputed. *(PR [#666](https://github.com/humlab-sead/sead_shape_shifter/pull/666))*
- Validation messages now display in a properly laid-out table, with long messages truncated with an ellipsis instead of breaking the layout. *(PR [#649](https://github.com/humlab-sead/sead_shape_shifter/pull/649))*
- Data-validation runs now honour which checks are selected. *(PR [#696](https://github.com/humlab-sead/sead_shape_shifter/pull/696))*

### Performance & Profiling

Text interpolation and concatenation in extra-column formulas are now computed column-wise instead of row-by-row, making normalization of text-heavy projects faster. A new `scripts/profile_normalization.py` tool reports per-entity times and the most expensive functions so slow normalization runs can be diagnosed. *(PR [#656](https://github.com/humlab-sead/sead_shape_shifter/pull/656))*

### Path Resolution & FK Linking Fixes

- Configuration directives such as `@include: ${GLOBAL_DATA_SOURCE_DIR}/sead-options.yml` now expand correctly when the directory is configured only in `.env`, and file paths that resolve through a symlink now log a warning naming the symlink and its target, making path-containment rejections easier to diagnose. *(PR [#653](https://github.com/humlab-sead/sead_shape_shifter/pull/653))*
- Foreign keys whose local key is a computed extra column based on an unnested column now link correctly during normalization instead of failing with a missing-column error. *(PR [#697](https://github.com/humlab-sead/sead_shape_shifter/pull/697))*

### Project Management

Administrators can duplicate a project and transfer its ownership in a single command: `project.sh copy --project X --to X-copy --owner B`. The command confirms before acting, supports dry-run, and preserves the copied files unchanged. *(PR [#704](https://github.com/humlab-sead/sead_shape_shifter/pull/704))*

### Maintainer Workflow Tools

- **Change PR workflow**: Run `scripts/create_change_pr.py` (or `make push-chore-pr` for the fast-track path) to branch, commit, open, and merge a change pull request with a template-conformant body. *(PR [#643](https://github.com/humlab-sead/sead_shape_shifter/pull/643))*
- **Description draft auto-commit**: When the change-PR workflow generates a description with Copilot, the draft file is now automatically committed and pushed to the pull request branch; pass `--no-commit-description-draft` to keep the previous manual behavior. *(PR [#644](https://github.com/humlab-sead/sead_shape_shifter/pull/644))*
- **Dev-to-staging promotion**: Prepare and publish a dev-to-staging promotion pull request with `scripts/promote_dev_to_staging.sh prepare` and `publish <pull-request-number>`, which handles provenance verification, draft PR creation, and description generation. *(PR [#659](https://github.com/humlab-sead/sead_shape_shifter/pull/659))*

### Developer & Testing Environment

- Integration tests that require a PostgreSQL database can now spin up and tear down a disposable container automatically, without needing a persistent instance. *(PR [#705](https://github.com/humlab-sead/sead_shape_shifter/pull/705))*
- Pyright type-checking errors were fixed and `pandas-stubs` added to the dev environment. *(PR [#633](https://github.com/humlab-sead/sead_shape_shifter/pull/633))*

### Minor UI

- The fixed values grid header elements are now spaced further apart (8 px instead of 4 px), giving the header a slightly more open layout. *(PR [#707](https://github.com/humlab-sead/sead_shape_shifter/pull/707))*

## Upgrade Notes

### Reconciliation ([#634](https://github.com/humlab-sead/sead_shape_shifter/pull/634), [#668](https://github.com/humlab-sead/sead_shape_shifter/pull/668), [#672](https://github.com/humlab-sead/sead_shape_shifter/pull/672))

- Existing `<project>-reconciliation.yml` files at version 2.0 (or without a version) are ignored with a warning on load. Recreate reconciliation specifications and rerun candidate matching to populate the new version 3.0 catalog.
- The mapping sidecar (`<project>-mapping.yml`) keeps its independent format; existing links continue to work, and `owner`, `verified_at`, and `local_only_approvals` are new optional fields written by the new export flow.
- The automatic `reconciliation_client` injection into the SEAD change request ingester is removed; remove any explicit injection or `reconciliation_query_columns` / `reconciliation_entity_types` configuration from custom setups.
- The `RECONCILE` planned-row action is renamed to `BLOCK_RECONCILIATION` (`reconcile` → `block_reconciliation`); update any code or tests referencing the old enum value.
- Database-sequence ID reservation can now consume a sequence value during both validation and ingestion, so unused ID gaps are expected.
- Existing specifications whose `property_mappings` reference properties no longer declared for the selected remote type remain saved but block candidate matching until the operator removes or remaps them in the editor.
- API consumers: the matching and suggestion endpoints can now return 400 (unsupported type or property mapping) and 503 (manifest unavailable or invalid, error code `RECONCILIATION_MANIFEST_ERROR`) where requests previously proceeded to the service.
- The reconciliation service must publish `reconciliation.supportedTypes` and a valid `extend.property_settings` array; the Authority Service-side contract change is tracked separately and is not part of this repository's diff. No data migrations are included.
- To enable SIMS contract registration, set `SHAPE_SHIFTER_SIMS_CONTRACT_CALLER` (defaults to `shape-shifter`) and `SHAPE_SHIFTER_SIMS_CONTRACT_REGISTRATION_TOKEN` to a token matching the SIMS caller entry. An unset token keeps registration closed, so Change Request runs stop before any identity work.
- Business-key edits on a bound project now save without a warning and are enforced by the next Change Request run. On an HTTP 409 conflict, either restore the registered key list and order or move the project to a new `metadata.provider_schema` value; SIMS exposes no update or retire call for a registered contract (see `docs/OPERATIONS.md#provider-scope-key-contract-conflicts`).
- Update links to the removed `docs/other/RECONCILIATION_SETUP_GUIDE.md` and `docs/other/RECONCILIATION_WORKFLOW.md`; both were replaced by `docs/other/RECONCILIATION_GUIDE.md`.

### Link Troubleshooter API & Environment ([#678](https://github.com/humlab-sead/sead_shape_shifter/pull/678), [#689](https://github.com/humlab-sead/sead_shape_shifter/pull/689), [#696](https://github.com/humlab-sead/sead_shape_shifter/pull/696))

- The stateless `POST /api/v1/projects/{project_name}/link-troubleshooter` route and its request and response models are removed. API consumers must migrate to `POST /api/v1/projects/{project_name}/link-experiment-contexts` (open), `POST .../{context_id}/trials` (trial), `GET .../{context_id}` (read the retained baseline), and `DELETE .../{context_id}` (release).
- Paging fields (`page`, `page_size`, `row_filter`) now return 422 on open and trial requests because the request models reject unknown fields.
- An expired context returns 410 with `detail.reason=context_expired` and must be reopened from the original warning request; unknown or foreign identifiers return a concealed 404. Context routes that previously returned 404 for unknown identifiers now return HTTP 410 with a recoverable stale-context detail.
- Deployers must rename the environment variable `SHAPE_SHIFTER_LINK_EXPERIMENT_GROUP_ROW_CAP` to `SHAPE_SHIFTER_LINK_TROUBLESHOOT_BROWSE_ROW_CAP`; its default is now 25,000 (maximum 25,000). Operators who set this variable explicitly should verify the value still suits their environment. Optional override: `SHAPE_SHIFTER_LINK_EXPERIMENT_MAX_MEMORY_MB` (default 100).
- The integrity troubleshooter API contract changed: the `page`, `row_offset`, and `row_limit` request fields were removed, and clients must use the new context-based flow via `POST …/integrity-troubleshooter/{context_id}/page` and `DELETE …/integrity-troubleshooter/{context_id}`. Baseline/trial responses now include only the first 100 rows per exception group, with remaining rows read from the new exception-rows endpoint, which requires `project:read` authorization.
- Retained contexts live in process memory, so the backend still requires a single Uvicorn worker, as now recorded in `docs/DESIGN.md`.

### Data Validation Default ([#676](https://github.com/humlab-sead/sead_shape_shifter/pull/676))

The default `validation_mode` on the data-validation endpoint changed from `sample` to `complete`. API callers that relied on the previous default should pass `validation_mode=sample` explicitly to retain the old behavior. The task-status gate continues to use sample mode internally and requires no caller change.

### Backend Deployers ([#633](https://github.com/humlab-sead/sead_shape_shifter/pull/633))

Project validation and ingestion now fail fast with a configuration error if `INGEST_TARGET_HOST`, `INGEST_TARGET_DBNAME`, or `INGEST_TARGET_USER` are unset, and ingesters registered for normalized-table input must implement the configured ingester lifecycle (Ingester plus table methods) or they are rejected with an explicit error.

### Developers ([#633](https://github.com/humlab-sead/sead_shape_shifter/pull/633))

Re-sync the development environment (e.g. `uv sync` with the dev extra) to pick up the new `pyright` and `pandas-stubs` packages.

### Change-PR Workflow ([#644](https://github.com/humlab-sead/sead_shape_shifter/pull/644))

No action is required. The new `--commit-description-draft` option defaults to on; users who prefer the old behavior (leaving the draft file for manual commit or discard) should pass `--no-commit-description-draft`.

### Project Deployment ([#704](https://github.com/humlab-sead/sead_shape_shifter/pull/704))

`sync-to-deploy` now compares files by checksum rather than modification time and no longer preserves source ownership or timestamps. Deployments relying on timestamp-based incremental sync will see a full content comparison on the first run after this change. No configuration changes are required.
