# What's New in v1.15.0

Date: 2026-01-29

## Changes

### [PR #183](https://github.com/humlab-sead/sead_shape_shifter/pull/183) Rename data entity type to entity and refactor dependency analysis

Entities previously configured with type: data are now configured as type: entity, shown in the UI
as "Data (Derived)". Editing entities is more reliable: the grid for fixed-value entities displays
correctly, columns are offered from the selected source entity, stale previews no longer linger when
switching entities, and CSV/Excel entity types appear with their own colors in the dependency
graph.

### [PR #184](https://github.com/humlab-sead/sead_shape_shifter/pull/184) Implement three\-tier identity system for entities

Entities now use a clearer three-part identity setup: a read-only, auto-numbered System ID, Business
Keys from your source data, and a required Public ID that names the primary key in the target
system and the foreign key columns in child entities. Existing configurations that use the old
surrogate_id field keep working and are automatically migrated to public_id.

### [PR #185](https://github.com/humlab-sead/sead_shape_shifter/pull/185) Introduce three\-tier identity system replacing surrogate\_id

Entities now use a clear three-part identity: an automatic local system_id, business keys from the
source data, and a required public_id that names the foreign key columns child entities receive, so
target-system IDs can be assigned directly in the entity editor. Legacy surrogate_id configurations
are still read and migrated automatically, and the entity editor now offers sheet and column pickers
for Excel-based entities.

## Upgrade Notes

### [PR #183](https://github.com/humlab-sead/sead_shape_shifter/pull/183)

Breaking configuration change: project YAML files must replace type: data with type: entity in
entity definitions and append entries — the backend model and validation no longer accept data as an
entity type. Omitted type now defaults to entity instead of data.

### [PR #184](https://github.com/humlab-sead/sead_shape_shifter/pull/184)

No manual migration is required: legacy surrogate_id configurations are automatically migrated to
public_id (in both the backend model and the frontend form), and public_id takes precedence if both
fields are present. However, validation has been tightened, so previously accepted configurations
may now report errors:

 - public_id (or legacy surrogate_id) is now required for fixed entities (error if missing).
 - An ID not ending with _id is now an error instead of a warning.
 - Foreign key columns in child entities are now named after the parent entity's public_id; verify
exported schemas if you relied on the previous naming.

### [PR #185](https://github.com/humlab-sead/sead_shape_shifter/pull/185)

- Rename entity type: data to type: entity in project YAML files: data is no longer an accepted
entity type in the backend model, schema, or frontend types (csv, xlsx, and openpyxl are now valid
types as well).
 - surrogate_id is deprecated: it is still accepted and automatically mapped to public_id, but new
configurations should set public_id (must end with _id; required for fixed-value entities). The
local identity column is standardized to system_id.
 - Per the implementation plan docs, no data migrations are required because the system is
pre-deployment and existing projects are test projects; projects/arbodat-test.yml in this branch
shows the updated conventions.
