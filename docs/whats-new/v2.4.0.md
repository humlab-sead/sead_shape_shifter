# What's New in v2.4.0

Date: 2026-10-26

## Changes

### [PR #528](https://github.com/humlab-sead/sead_shape_shifter/pull/528) Fix entity name validation, guarded renames, and foreign key handling

You can now rename an entity directly in the entity editor: the rename is blocked with a clear list
of the entities that reference it if any dependencies exist, and otherwise updates the project
(including its default entity) and moves the entity's note automatically. New entity names must be
at least two characters and use lowercase letters, digits, and underscores starting with a letter,
and foreign key testing now waits until unsaved entity changes are saved.

### [PR #529](https://github.com/humlab-sead/sead_shape_shifter/pull/529) feat: stage\-aware column suggestions for the entity editor

Column pickers in the entity editor now suggest the columns that are actually available at each step
of the entity's pipeline — for example, columns added by a foreign-key link or by unnesting —
instead of one mixed list everywhere. Suggestions update as you edit an unsaved entity, and you can
still type any column name.

### [PR #540](https://github.com/humlab-sead/sead_shape_shifter/pull/540) feat\(core\): make business keys declarative over produced columns

Business keys now only label fields an entity actually produces: you no longer need to duplicate
keys into columns, and if a key is not produced, validation and the UI report exactly which field is
missing and how to fix it. Fixed-entity tables no longer gain empty key columns.

### [PR #542](https://github.com/humlab-sead/sead_shape_shifter/pull/542) feat\(container\): versioned releases and setup simplification

Administrators can now install, select, and roll back versioned container releases
(container-vX.Y.Z) per environment through a single host script, without changing the application
image settings. Entity configurations can also use the system-generated ID columns as business keys
without triggering false missing-key or duplicate-scan errors, and the task graph's "has note"
filter no longer shows untracked entities.

### [PR #543](https://github.com/humlab-sead/sead_shape_shifter/pull/543) Container setup simplification: Phase 3 and deployment/ restructure

Container lifecycle and service control now run through one entry point, scripts/container.sh
(including container.sh service <action> for the systemd user service), and project adoption/moves
use a single scripts/project.sh adopt|move command. Deployment defaults now come from one shared
template, so a fresh checkout and an initialized deployment resolve the same values.

### [PR #546](https://github.com/humlab-sead/sead_shape_shifter/pull/546) refactor\(ingester\): rename delivery terminology to MVP

The SEAD Change Request Ingester now describes its output as an "MVP Delivery" change package
instead of "Delivery 1" in operator-facing messages, the frontend workflow alert, and generated
package metadata (artifact_type is now mvp_delivery_change_package).

### [PR #547](https://github.com/humlab-sead/sead_shape_shifter/pull/547) Sync PostgreSQL sequences after inserting SIMS\-assigned IDs

Generated deployment packages now keep SEAD database ID sequences ahead of the submission and
dataset IDs assigned by SIMS, so later database-generated IDs no longer collide with IDs inserted by
a package.

### [PR #549](https://github.com/humlab-sead/sead_shape_shifter/pull/549) Share target models across projects

The project metadata target model picker now lists shared YAML target models alongside project-local
files, so teams can maintain one shared model that multiple projects use without copying it. Shared
models are read-only in the project editor; project-local models remain editable.

### [PR #552](https://github.com/humlab-sead/sead_shape_shifter/pull/552) feat\(target\-model\): enforce conditional FKs after reconciliation

Target-model authors can now mark a foreign key as required only when a change request actually
inserts new rows, using required_when: {has_new_rows: <entity>}. A submission whose rows all match
existing records no longer fails on that link requirement, while new rows with a missing or
unresolvable link value are rejected before the change request is accepted. The validation panel
also shows conditional checks that await reconciliation instead of hiding them.

### [PR #562](https://github.com/humlab-sead/sead_shape_shifter/pull/562) Sync mapping links after fixed entity saves

Saving a fixed entity now updates its mapping links only where you changed IDs or row keys, leaving
other links and their history intact, and if the mapping update fails after the rows are saved the
editor reports a partial save with a Retry mapping action. The "Sync from materialized entity" admin
operation now only adds missing links unless you explicitly ask it to replace manual links.

### [PR #563](https://github.com/humlab-sead/sead_shape_shifter/pull/563) Retire release manager; manual deployment files, NGINX bootstrap

Deploying an environment no longer requires the release manager: operators place or refresh the
deployment files in ~/container with a copy or sync-to-deploy, and the NGINX installer can now set
up an HTTP-only bootstrap site so a TLS certificate can be obtained before the HTTPS site is
enabled.

### [PR #565](https://github.com/humlab-sead/sead_shape_shifter/pull/565) Add deployment\-time staging for change\-request ingester

Deployers can now select the new inline_staging deploy strategy, which lets submitted child rows
omit target IDs: the database assigns them when the release SQL runs, so bundles no longer reserve
IDs that may never be deployed.

### [PR #568](https://github.com/humlab-sead/sead_shape_shifter/pull/568) Bind projects to provider\-schema scopes \(Phases 1\-4\)

When creating a project, users now pick a registered data provider and provider schema, and that
choice is fixed once assigned. SEAD Change Request runs always use the open project's registered
scope and provider row, and the result now shows the SIMS scope and run ID used, so an operator can
match an emitted bundle to the run that produced it.

### [PR #570](https://github.com/humlab-sead/sead_shape_shifter/pull/570) Add in\-memory project handoff for Change Request ingester

Operators can now validate a saved project and generate its SEAD Change Request deploy bundle
directly from the project's Dispatch tab, without a workbook path or a prior Execute run. The old
Change Request file-upload workflow is retired and now returns a clear "file input retired" error.

### [PR #572](https://github.com/humlab-sead/sead_shape_shifter/pull/572) Support project\-only change request bundles

Operators with Execute access to a saved project can now validate and create SEAD Change Request
bundles from that project without a separate application-level ingester permission, and each run
writes to its own dated run folder whose path is reported in the response. When a Binding Set awaits
confirmation, the guidance now shows the exact run ID to reuse for the retry.

### [PR #574](https://github.com/humlab-sead/sead_shape_shifter/pull/574) Add project file sharing and reconciliation YAML support

In the project Files tab you can now replace an existing file when uploading a same-named one,
delete files that no entity uses, and — if you have shared-source permission — share a copy of a
project file with all projects; accessible shared files also appear in the list as read-only. YAML
editors for reconciliation specifications and catalogs now offer autocomplete and validation from a
generated schema.

### [PR #586](https://github.com/humlab-sead/sead_shape_shifter/pull/586) Remove deprecated SEAD ingester; fix grants, project switch, notes

Clearing a project node's note and saving now deletes the note, and validation results no longer
carry over when you switch projects. The legacy SEAD Clearinghouse ingester has been removed; the
SEAD Change Request ingester is now the only available ingester, and invalid grant role names are
rejected with an error listing the valid roles instead of being silently ignored.

### [PR #588](https://github.com/humlab-sead/sead_shape_shifter/pull/588) fix\(auth\): authorize project data\-source connections from body source

Connecting a shared data source (such as SEAD) to a project from the Connect dialog no longer fails
with a 404 "Resource not found" error for users who have access to the project and the selected
source.

### [PR #590](https://github.com/humlab-sead/sead_shape_shifter/pull/590) Implement direct target ID foreign keys

Projects can now declare that a change-request foreign-key column already contains an existing SEAD
target ID (foreign_key_value_sources: <target>: public_id), so that relationship no longer needs a
helper project entity to translate local IDs. The ingester verifies every supplied ID against the
target database before accepting the package, and the package manifest records which foreign keys
used direct target IDs.

### [PR #604](https://github.com/humlab-sead/sead_shape_shifter/pull/604) Add data validation run status and fix unnest and data\-source bugs

The validation panel now shows how a data-validation run actually executed: the selected mode, an
overall run status, and per-entity results with reasons when a check failed or was skipped, so
silent gaps in validation are visible. Unnest configurations that list a column in both id_vars and
value_vars now work (the column is kept as an identifier with a warning) instead of being rejected,
and entities can be generated from tables backed by shared @include data sources.

## Upgrade Notes

### [PR #528](https://github.com/humlab-sead/sead_shape_shifter/pull/528)

- API consumers of the project restore endpoint must send {"backup_name": ...} instead of
{"backup_path": ...}; BackupInfo responses no longer include file_path, and the backups list only
contains shapeshifter.yml configuration backups.
 - New entity names and rename targets must match ^[a-z][a-z0-9_]*$ with at least two characters;
existing entities with non-conforming names are not renamed automatically.
 - Renames made by editing project YAML directly still require manually updating references and any
task sidecar keys; note migration through the API is best-effort and a warning identifies when
manual note recovery is needed.

### [PR #540](https://github.com/humlab-sead/sead_shape_shifter/pull/540)

- The authoritative fixed-entity column order changed from system_id → public_id → keys → data
columns to system_id → public_id → data columns. The values API still accepts the previous order for
recognized legacy requests and reorders rows by name, so existing saved files continue to work.
 - Entity configurations that list business keys the entity does not produce now fail structural
validation, fixed-schema checks, and data validation. Add the missing fields to columns or configure
the producer (extra_columns, foreign_keys, or unnest) that creates them. The PR author reports a
survey found no existing project configuring an unproduced business key.
 - Retiring the legacy fixed-values request-order path is deferred to a follow-up (#539); the 
compatibility path only accepts additional input shapes and is backward-compatible.

### [PR #542](https://github.com/humlab-sead/sead_shape_shifter/pull/542)

Existing container deployments must move to the release flow:

 1. Install the host manager once: sudo install -o root -g root -m 0755
container/scripts/deploy/manage_container_release.sh
/usr/local/sbin/shape-shifter-container-release.
 2. Move a pre-release ~/container directory aside (e.g. sudo -u USER mv ~/container
~/container.pre-release), then install and activate an exact release; activate refuses to replace a
real directory.
 3. Reinstall the systemd unit (make service-install) because it now starts the container through
scripts/container.sh; the removed scripts up.sh, down.sh, logs.sh, and status.sh no longer exist —
use the make targets or scripts/container.sh <action>.
 4. Check relative path overrides: a relative CONFIG_DIR/DATA_DIR/CONTAINER_DATA_DIR in
~/config/deployment.env now resolves under the user's home, not beside the checkout, so the old
DATA_DIR=../container-data spelling must be rewritten (e.g. DATA_DIR=container-data).
 5. The removed Make targets setup-env and setup-directories have no replacement targets; use make
setup.

~/config and ~/container-data are untouched by release install, activation, and rollback. See
container/DEPLOYMENT.md ("Install and select a container release" and the migration sections) for
the full procedure.

### [PR #543](https://github.com/humlab-sead/sead_shape_shifter/pull/543)

- In a repository checkout, deployment files now live under deployment/container/ (run make targets
there) and host tools under deployment/container-host/deploy/; update any scripts, cron jobs or
runbooks that reference the old container/... paths.
 - bootstrap-authentication-and-authorization.sh no longer derives CONFIG_DIR from the checkout
location: it must be set explicitly (e.g. CONFIG_DIR=$HOME/config).
 - Replace calls to scripts/service.sh <action> with scripts/container.sh service <action>, and
adopt-project.sh/move-project.sh with project.sh adopt/project.sh move.
 - Installed releases are unaffected: the release archive root remains container/ and installs to
the deployment user's ~/container as before; no migration of ~/config or ~/container-data is
required.

### [PR #546](https://github.com/humlab-sead/sead_shape_shifter/pull/546)

Consumers or tooling that read generated package metadata and match on artifact_type must look for
mvp_delivery_change_package instead of delivery_1_change_package. The metadata contract_version is
unchanged (1), and no migrations or configuration changes are otherwise required.

### [PR #547](https://github.com/humlab-sead/sead_shape_shifter/pull/547)

- The new synchronize_sequence_after_insert flag defaults to false, so existing custom target
models are unaffected unless opted in.
 - Deployers: the updated documentation states that upstream SEAD schema deployment and legacy
compatibility remain release dependencies outside this repository; generated packages are only
eligible once those are deployed.
 - Note for operators: sequence advancement is not undone if a package transaction fails, so a retry
can leave gaps in the target sequence (IDs are skipped, not reused).

### [PR #552](https://github.com/humlab-sead/sead_shape_shifter/pull/552)

- No migration is required, and existing models with unconditional required flags keep their
current validation results.
 - resources/target_models/sead_minimal_model.yml has been removed; anyone referencing it must
switch to another target model.
 - The shipped sead_superset_model.yml now marks master_dataset, data_provider, citation, and
contact as required: true; projects validated against the superset model may need to include these
entities.
 - To use the new rule, omit unconditional required: true on the lookup entity and FK column, per
the target-model guide; the rule is not yet activated in the superset model.

### [PR #562](https://github.com/humlab-sead/sead_shape_shifter/pull/562)

- Breaking behavior change for API consumers: PATCH
/projects/{project}/mapping/from-materialized/{entity} no longer replaces all manual links when
called without a body; it now only adds links at absent keys. Callers that relied on full
replacement must send {"replace_manual_links": true}. The response adds manual_links_added and keeps
manual_links_replaced (zero in additive mode).
 - Renaming an entity that has a mapping sidecar entry now fails with HTTP 409; remove or migrate
that entry before renaming.
 - No data migrations are required; the mapping sidecar schema and normalization precedence are
unchanged.

### [PR #563](https://github.com/humlab-sead/sead_shape_shifter/pull/563)

- Hosts that installed /usr/local/sbin/shape-shifter-container-release no longer need it; the host
tools now accept a real ~/container directory holding the deployment/container/ tree (with Makefile
and VERSION). Environments whose ~/container is still a symlink into /opt/shape-shifter/ must have
that symlink reviewed and removed before placing a real directory.
 - Refresh deployment files with deployment/container-host/deploy/sync-to-deploy --deploy-user USER,
then reinstall and restart the systemd unit (make service-install / systemctl --user -M USER@
restart shape-shifter). The manual layout keeps no previous version on the host: roll back by
syncing a checkout at an earlier commit.
 - install_nginx_reverse_proxy.sh now requires an existing certificate for the HTTPS vhost. On hosts
without one, run it with --bootstrap first, obtain the certificate with certbot certonly --webroot
-w /var/www/html -d <DOMAIN>, then re-run without --bootstrap. It also rejects DOMAIN/UPSTREAM_PORT
values that are not a plain hostname and numeric port.
 - The container-release workflow still publishes container-vX.Y.Z tags, but no environment consumes
them.

### [PR #565](https://github.com/humlab-sead/sead_shape_shifter/pull/565)

No action is required for existing workflows; the current direct-insert and copy-CSV artifacts
remain the default. To use the new strategy, set deploy_strategy to inline_staging and supply a
non-empty staging_target_schema (relation names are ambiguous across the public and clearing_house
schemas, so the schema must be explicit). The staging_target_schema option is rejected for the other
strategies. Children of value_type roots remain unsupported until a deployed ID generator exists
for value_type_item; such rows are rejected explicitly rather than silently skipped.

### [PR #568](https://github.com/humlab-sead/sead_shape_shifter/pull/568)

- Deployers must provide the data provider registry directory: the new
SHAPE_SHIFTER_GLOBAL_DATA_PROVIDER_DIR setting (default shared/data-providers) must contain valid
provider YAML files. In the container it is mounted read-only from the image at
/app/shared/data-providers and must not be overridden.
 - Breaking API changes: project creation now requires data_provider_code and provider_schema
(missing fields return 422, unregistered pairs 400); SEAD Change Request validate/ingest require a
top-level project_name for an authorized saved project, and a caller-supplied sims_scope_name is
rejected.
 - An assigned provider-schema pair cannot be changed or removed through the application; tracked
entities in Change Request runs must declare valid business keys, or the run is blocked before any
SIMS or target-database access.
 - Existing unbound projects keep working unbound; moving them to provider scopes is deferred to the
separate cutover proposal and requires operator action per project.

### [PR #570](https://github.com/humlab-sead/sead_shape_shifter/pull/570)

- Deployers who want the project-based Change Request workflow must configure
SHAPE_SHIFTER_INGEST_TARGET_HOST, SHAPE_SHIFTER_INGEST_TARGET_PORT,
SHAPE_SHIFTER_INGEST_TARGET_DBNAME, SHAPE_SHIFTER_INGEST_TARGET_USER, and a writable
SHAPE_SHIFTER_INGEST_OUTPUT_DIR (relative paths resolve under SHAPE_SHIFTER_APPLICATION_ROOT); the
target password belongs in the deployment user's PostgreSQL password file, not in env files. The
workflow fails with a configuration error until these are set.
 - Breaking for API consumers: POST /api/v1/ingesters/sead_change_request/validate and /ingest now
return HTTP 400 for file input. Callers must switch to the new from-project/validate /
from-project/ingest routes with the strict project request body. Other ingesters' file routes are
unchanged.
 - No database migrations are included.

### [PR #572](https://github.com/humlab-sead/sead_shape_shifter/pull/572)

- Bundle output location changed: bundles are nested under a run folder (<UTC
timestamp>_<sha256(run_id)>/<bundle_name>) instead of directly under the output root. Consumers
should use the output_path returned in the ingest response rather than reconstructing paths from the
bundle name.
 - Callers that relied on generation-time reservation of database-sequence public IDs must
pre-resolve those IDs before validation or ingestion; the optional target_id_allocator collaborator
was removed and unresolved IDs are now blocked.
 - Code that constructs ProjectIngesterService must drop the authorization_service constructor
argument.
 - No database migrations or configuration changes are required.

### [PR #586](https://github.com/humlab-sead/sead_shape_shifter/pull/586)

- Any deployment that enabled the sead ingester must remove it from
SHAPE_SHIFTER_ENABLED_INGESTERS; the value is a JSON list (e.g. '["sead_change_request"]'), and the
backend env example now ships that default.
 - API or CLI callers using the sead ingester key (e.g. POST /api/v1/ingesters/sead/validate|ingest,
python -m backend.app.scripts.ingest ... sead) must move to sead_change_request and its
project-only routes; the removed key no longer resolves.
 - Authorization manifests and state snapshots that contain a role not defined for a resource type
will now fail to apply or import until corrected; fix the role spelling first. The
sead-authorization grant CLI likewise accepts only known role names.

### [PR #590](https://github.com/humlab-sead/sead_shape_shifter/pull/590)

No action is required for existing projects: an omitted or system_id declaration keeps the current
local-link behavior and package output. Projects that adopt public_id mode must resolve
metadata.target_model, output the target FK column, avoid a conflicting Core foreign_keys link to
the same target, and have the target database reachable, because the read-only ID lookup is
mandatory and validation/ingestion fail when it is unavailable. Change-request manifests may now
include a new direct_target_id_foreign_keys entry when a package uses direct IDs.

### [PR #604](https://github.com/humlab-sead/sead_shape_shifter/pull/604)

No configuration migration is required. Note one behavior change: an unnest configuration with
overlapping id_vars/value_vars columns previously failed structural validation and now passes with a
warning; at runtime the overlapping columns are kept as identifiers and excluded from the melted
values, and if every value_vars column overlaps, the entity is marked incomplete rather than the
project failing at unnest.
