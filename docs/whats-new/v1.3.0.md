# What's New in v1.3.0

Date: 2026-01-13

## Changes

### [PR #139](https://github.com/humlab-sead/sead_shape_shifter/pull/139) Fix \#137: rename "ingest" to "dispatch" and move into project editor

Dispatching processed data to a target system now lives inside each project as a "Dispatch" tab
instead of a separate "Data Ingestion" page, and the interface uses "dispatch" wording throughout,
making the delivery step part of the project workflow. When the frontend is served by the backend,
API calls now correctly go to the same origin.

### [PR #142](https://github.com/humlab-sead/sead_shape_shifter/pull/142) Edit entities from the graph view with overlay editor and context menu

You can now edit an entity directly from the dependency graph by double-clicking its node, which
opens the editor as an overlay without leaving the graph. Right-clicking a node opens a context menu
to preview the entity's data, duplicate the entity, or delete it.

### [PR #144](https://github.com/humlab-sead/sead_shape_shifter/pull/144) feat\(docker\): Serve frontend from backend in single container \(\#143\)

Shape Shifter now runs as a single Docker container: the UI and API are both available at
http://localhost:8012, so deployment is just creating the data directories and running 
docker-compose up -d --build — no separate frontend container or port 80 mapping is needed.

### [PR #145](https://github.com/humlab-sead/sead_shape_shifter/pull/145) Rename ingest to dispatch, add graph editing and unified Docker setup

Data dispatch (formerly "Data Ingestion") now lives in a Dispatch tab inside each project, so you
configure and send data to the target system without leaving the project editor. In the dependency
graph you can now double-click an entity to edit it in an overlay and right-click for preview,
duplicate and delete actions.

## Upgrade Notes

### [PR #139](https://github.com/humlab-sead/sead_shape_shifter/pull/139)

- When deploying the frontend served by the backend, build it with the production environment
(VITE_API_BASE_URL="", e.g. via make br+fr or pnpm build:skip-check in frontend/) so same-origin API
calls work; a related open issue (#138, "Wrong VITE_API_BASE_URL when front end served via 
backend") is tracked in TODO.md.
 - The standalone /ingesters route and its sidebar link were removed; users should use the Dispatch
tab in the project editor instead.

### [PR #144](https://github.com/humlab-sead/sead_shape_shifter/pull/144)

- The compose stack changed from two services (backend, frontend) to one (app). Stop the old stack
(docker-compose down), optionally remove the old shapeshifter-backend/shapeshifter-frontend images,
then rebuild with docker-compose up -d --build.
 - The frontend is no longer served on port 80; access the UI at http://localhost:8012/. Update 
bookmarks, reverse proxies, and firewall rules accordingly.
 - Create the expected data directories before starting: mkdir -p projects input output backups
logs.
 - The previous docker/data/ env-file setup (backend.env, frontend.env) is no longer the documented
flow; configure runtime variables in docker-compose.yml or a .env file, and frontend build-time
variables under build.args (these require an image rebuild to change). docker/ENV_VARIABLES.md was
removed; see the rewritten docker/README.md.
 - make docker-setup and make docker-test were removed; use the new targets (e.g. make docker-build,
make docker-rebuild, make docker-health) or docker/test-build.sh.

### [PR #145](https://github.com/humlab-sead/sead_shape_shifter/pull/145)

- The Docker setup is now a single app container; the separate backend and frontend services are
gone. Stop the old stack (docker-compose down), then rebuild and start with docker-compose up -d
--build. Only port 8012 is exposed (the frontend is served by the backend).
 - Create the required directories before starting: mkdir -p projects input output backups logs.
Runtime data is mounted from these host directories instead of the previous docker/data/ env-file
setup; docker/ENV_VARIABLES.md has been removed and docker/README.md documents the new
configuration.
 - The /ingesters page has been removed; use the Dispatch tab in the project detail view instead.
