# What's New in v1.4.0

Date: 2026-01-14

## Changes

### [PR #146](https://github.com/humlab-sead/sead_shape_shifter/pull/146) fix\(docker\): additional fixes related to docker \(\#143\)

Docker startup, restart, and logs now work from the repository root via the Makefile targets, and
the container's configuration comes entirely from docker/data/backend.env, so what you see in that
file is what the application actually uses.

### [PR #147](https://github.com/humlab-sead/sead_shape_shifter/pull/147) Simplify Docker Compose setup and clean up backend imports

The Docker helper commands (make docker-up, docker-down, docker-logs, docker-restart, etc.) are
simplified, and the reported application URL now reflects the configured backend port instead of a
fixed port number.

### [PR #148](https://github.com/humlab-sead/sead_shape_shifter/pull/148) Add GitHub build mode and non\-root runtime user to Docker build

You can now build the Shape Shifter Docker image directly from the GitHub repository (a branch, tag,
or fork) instead of only from your local checkout — for example make docker-build-github or make
docker-build-tag TAG=v1.2.0 — and the application container now runs as a non-root user for improved
security.

### [PR #149](https://github.com/humlab-sead/sead_shape_shifter/pull/149) Support GitHub and local build modes in Dockerfile, run as non\-root

You can now build the Shape Shifter Docker image directly from GitHub (a branch or a specific tag)
in addition to building from your local checkout, and the application container runs as a non-root
user for improved security.

## Upgrade Notes

### [PR #146](https://github.com/humlab-sead/sead_shape_shifter/pull/146)

Deployers must ensure all runtime variables (application settings and SEAD database connection
details) are defined in docker/data/backend.env: the compose file no longer injects inline defaults
such as SHAPE_SHIFTER_ENVIRONMENT=production or the various SHAPE_SHIFTER_* defaults, so anything
previously covered by those inline values must now be provided in the env file. The Makefile's
docker start messages display ${BACKEND_PORT}; set that variable if you rely on the displayed URL
(the compose host port itself still falls back to HOST_PORT:-8012).

### [PR #147](https://github.com/humlab-sead/sead_shape_shifter/pull/147)

- The compose file no longer sets inline defaults for SHAPE_SHIFTER_* and SEAD_* environment
variables; all container environment settings must be provided in docker/data/backend.env. Deployers
should verify that file defines the settings they rely on (e.g. SHAPE_SHIFTER_ENVIRONMENT,
SHAPE_SHIFTER_ALLOWED_ORIGINS), since values previously defaulted in the compose file are no longer
injected there.
 - The obsolete version: '3.8' key was removed from docker-compose.yml; no action is needed for
Docker Compose v2 users.
 - httpx is now a required runtime dependency rather than a dev-only one; a normal dependency
install picks this up automatically.

### [PR #148](https://github.com/humlab-sead/sead_shape_shifter/pull/148)

- The container now runs as the non-root user shapeshifter (uid/gid 1000). Host directories mounted
into the container (projects, logs, output, backups, tmp) must be readable and writable by uid/gid
1000, or the application may fail to start or write data.
 - Docker recipes moved to docker/Makefile; root-level make docker-* commands keep working via an
include, and the targets also work from the docker/ directory (make -f Makefile docker-build).
 - The updated README quick start uses data/ subdirectories (e.g. data/projects, data/logs) for
local mounts; existing deployments using the previous flat layout should verify their compose volume
configuration still matches.

### [PR #149](https://github.com/humlab-sead/sead_shape_shifter/pull/149)

- The container now runs as a non-root user with uid/gid
  1000. If you bind-mount host directories (projects, logs, output, backups, tmp), make sure they
are writable by uid/gid 1000, otherwise the application may fail to write data.
 - Existing make docker-* commands from the repository root keep working; they are now provided by
the included docker/Makefile. New optional targets are make docker-build-github and make
docker-build-tag TAG=v1.2.0.
 - The updated docker/README.md quick start creates data directories under data/ (e.g.
data/projects, data/logs) instead of top-level directories; follow the current README for the
expected layout.
