# What's New in v2.1.0

Date: 2026-09-09

## Changes

### [PR #415](https://github.com/humlab-sead/sead_shape_shifter/pull/415) Add async SIMS client for sead\_authority\_service identity endpoints

User-visible impact not verified.

### [PR #429](https://github.com/humlab-sead/sead_shape_shifter/pull/429) Add DuckDB loader and TableStore hooks for SQL\-derived entities

Projects can now define an entity with type: duckdb and a plain SQL query to join, aggregate, or
filter data from entities that were already processed, without configuring an external database. The
processed entities appear automatically as SQL views, so cross-entity derivations no longer need
workarounds in expressions or downstream tools.

### [PR #433](https://github.com/humlab-sead/sead_shape_shifter/pull/433) Coerce and validate fixed\-entity column types for safer FK linking

Fixed lookup-table values are now handled with consistent types: integer IDs are recognized and
normalized automatically, pasted or typed values in _id columns are validated in the grid, and
projects that needed load-time cleanups show a "Load-Time Normalizations Detected" banner so you can
review and save them deliberately. Projects can also declare explicit column types (column_types)
for fixed columns that should be treated as int, float, bool, or date.

### [PR #434](https://github.com/humlab-sead/sead_shape_shifter/pull/434) feat\(frontend\): add fixed entity column type editing

When editing a fixed entity, each column now has a type selector so values can be declared as
integers or strings, with invalid entries highlighted directly in the grid and summarized per
column. Column types already declared in the entity definition (such as dates) are preserved when
saving instead of being lost.

### [PR #436](https://github.com/humlab-sead/sead_shape_shifter/pull/436) Add project\-level fixed\-entity type conventions

Projects can now define reusable type conventions for fixed-entity columns once at the project level
(for example, all columns matching abundance are treated as int), instead of repeating column_types
on every entity. Matching columns are coerced and validated consistently when projects load, save,
and materialize, while per-entity column_types still override conventions.

### [PR #443](https://github.com/humlab-sead/sead_shape_shifter/pull/443) Add sead\_change\_request ingester for Delivery 1 change packages

A new SEAD change request ingester turns a submission (Excel workbook or in-memory tables) into a
forward-only deploy package — deploy SQL plus metadata — once the SIMS Binding Set is confirmed, and
returns a clear report naming the blocked entities and the confirmation step needed when it cannot
proceed.

### [PR #445](https://github.com/humlab-sead/sead_shape_shifter/pull/445) feat\(ingesters\): add deploy strategies and align follow\-up docs

Change-request artifact bundles can now be generated either as inline INSERT SQL or as a CSV-based
bundle with gzip payloads and \copy deploy statements, selected via a deploy_strategy setting.
Bundles use a standard YYYYMMDD_DML_<datatype>_<IDENTIFIER> layout with deploy/revert/verify folders
and a manifest, and submission metadata (datatype, identifier, description, author, issue) is
validated and embedded in the generated SQL headers.

### [PR #454](https://github.com/humlab-sead/sead_shape_shifter/pull/454) feat\(target\-model\): complete SEAD target\-model follow\-up tranche

Shape Shifter now ships a much broader bundled SEAD target model (92 entities) covering sample and
sample-group context, site/feature properties, generic typed analysis values, value qualifiers,
taxonomy/Red Data Book lookups, and project classification vocabularies, so projects can validate
against a near-complete SEAD model and select curated subsets. Target-model validation now reports
precise specification errors (such as unknown foreign-key targets or invalid aggregate-parent
setups) instead of a generic invalid-model error, and model documentation can be generated as a SIMS
entity register.

### [PR #456](https://github.com/humlab-sead/sead_shape_shifter/pull/456) Add sead change request workflow UX and target\-model schema reference

Operators can now run the SEAD change request workflow from the ingester form with guided operator
inputs, clear Binding Set confirmation guidance when a run is blocked, and a deploy-package summary
with handoff instructions after a successful run. Project workspaces also offer a new "Schema
Reference (Markdown)" target-model documentation download generated from the schema.

### [PR #458](https://github.com/humlab-sead/sead_shape_shifter/pull/458) feat\(target\-model\): finish conformance backlog rollout

Target-model conformance now reports findings at the right level of urgency: new checks catch
orphaned fact entities and append sources that omit required target columns, transitive foreign-key
paths no longer produce false errors, and projects can silence or re-rank individual conformance
rules in their YAML. Target models can also declare generated columns and enum allowed values, which
the validator now understands and enforces.

### [PR #464](https://github.com/humlab-sead/sead_shape_shifter/pull/464) Add graphify knowledge graph and assistant hooks

Contributors and AI coding assistants now work against a committed project knowledge graph: graphify
query, graphify explain, and graphify path return focused subgraph answers, and assistant hooks
automatically steer codebase lookups toward these commands instead of full-file reads.

### [PR #466](https://github.com/humlab-sead/sead_shape_shifter/pull/466) Consolidate ID mapping persistence into a mapping sidecar file

Confirmed reconciliation links can now be saved to a single mapping file (<project>-mapping.yml)
with the new "Export to Mapping" button, and IDs assigned on materialized entities are automatically
kept there, so they survive unmaterializing and rematerializing an entity. During normalization
these saved links populate the target ID columns, with manual assignments taking priority over
reconciliation matches.

### [PR #467](https://github.com/humlab-sead/sead_shape_shifter/pull/467) Overhaul configuration module and ingester registry access

Project task progress now stays up to date when projects are served from the application cache, so
task states such as completed or ignored steps are reflected immediately after they change.

### [PR #469](https://github.com/humlab-sead/sead_shape_shifter/pull/469) Resolve config paths under application root and add @load directive

Project files now reference their target model with @load: (e.g. target_model: '@load:
sead_standard_model.yml'), and the web editor's target-model combobox writes this prefix; existing
@include: references still resolve. Relative path settings (projects dir, log dir, global data
paths) now resolve against the application root regardless of the working directory the app is
started from, making behavior consistent between the API, CLI, and tests.

### [PR #470](https://github.com/humlab-sead/sead_shape_shifter/pull/470) Add semantic rules catalog and loader options schema generation

Project YAML editing in the Monaco editor now autocompletes loader options (filename, sheet_name,
range, etc.) and previously undocumented entity fields such as replacements and defer_dependency,
and AI assistants can validate project files against a machine-readable rule catalog that flags
common mistakes like a missing options.filename on an Excel entity.

### [PR #471](https://github.com/humlab-sead/sead_shape_shifter/pull/471) Implement existing\-row updates and submission outcome classification

The change-request ingester can now handle corrections to existing rows: submissions are classified
into outcomes (new data, no-op, allowed update, pending review, blocked), and accepted updates to
configured mutable fields are delivered as explicit UPDATE statements in the deploy artifact, while
ambiguous or out-of-scope changes are blocked with clear diagnostics instead of being applied
silently.

### [PR #477](https://github.com/humlab-sead/sead_shape_shifter/pull/477) Persist SEAD change request submission metadata

SEAD change request runs now remember stable values such as datatype, deploy strategy, and author
per project, so the ingester form opens prefilled and reruns stay consistent. Each run also records
a submission in SEAD that references the project's data provider and groups the newly delivered
datasets.

### [PR #482](https://github.com/humlab-sead/sead_shape_shifter/pull/482) chore: sync main with dev test release \(ingester, policies, docs\)

Shape Shifter now includes a SEAD change-request ingester that turns source submissions into
reviewed change-request packages, and per-entity reconciliation policies help match incoming rows
against existing SEAD data. The project editor also gains an improved fixed-values grid and a DuckDB
data loader.

## Upgrade Notes

### [PR #429](https://github.com/humlab-sead/sead_shape_shifter/pull/429)

- The duckdb Python package (>=1.5.2) is now a required dependency; reinstall dependencies (e.g. uv
sync) after upgrading.
 - No configuration changes are required for existing projects; the new type: duckdb is opt-in. Note
that GET /data-sources/drivers no longer returns internal-category drivers, and a new GET
/data-sources/entity-types endpoint is available for UI type selectors.

### [PR #433](https://github.com/humlab-sead/sead_shape_shifter/pull/433)

- No migration is required; column_types is optional and existing projects load unchanged.
 - Behavior change to be aware of: coercible values in _id columns (e.g. "53") are normalized in
memory on load and only written back to YAML on explicit save; invalid non-empty _id values (e.g.
"abc", "53.0", booleans) are now rejected by validation and save paths instead of being coerced to
null. Fix such values in project YAML if saves fail.
 - After deployment, operators should open a representative project with fixed entities and check
for the load-time normalization banner, per the added guidance in docs/OPERATIONS.md.

### [PR #443](https://github.com/humlab-sead/sead_shape_shifter/pull/443)

API consumers of the ingester endpoints should note the response changes: failed ingestions now
return HTTP 200 with a structured response (success: false, error_details) instead of HTTP 500 with
a detail message, and validate/ingest responses carry new optional fields (infos,
pending_confirmation_report, deploy_artifact, error_details). Generated deploy packages are
forward-only: revert.sql and verify.sql are placeholders and the metadata marks the package as
non-revertible. No migrations or configuration changes are included in the diff.

### [PR #445](https://github.com/humlab-sead/sead_shape_shifter/pull/445)

- The emitted bundle layout changed: deploy.sql/revert.sql/verify.sql/metadata.json in a sanitized
folder are replaced by deploy/<bundle>.sql, revert/<bundle>.sql, verify/<bundle>.sql, and
manifest.json under the canonical bundle name. Downstream consumers of the old layout must be
updated.
 - submission_context now requires datatype (from the approved set) and identifier; multiline or
≥80-character descriptions are rejected.
 - Renamed public APIs: materialize_resolved_tables → project_target_ids,
check_materialized_collisions → check_projected_collisions, MaterializationResult/MaterializedTable
→ TargetProjectionResult/ProjectedTable, and DeployArtifact fields
revert_placeholder_sql/verify_placeholder_sql → revert_sql/verify_sql.

### [PR #454](https://github.com/humlab-sead/sead_shape_shifter/pull/454)

- Update project metadata.target_model references from sead_standard_model.yml to
resources/target_models/sead_superset_model.yml where the bundled SEAD spec is intended; all docs
and manual-test fixtures now point at the superset file.
 - Target model YAML is parsed strictly: unknown keys in model, entity, column, foreign-key, naming,
constraint, or metadata blocks now raise a load error instead of being ignored. Review custom specs
for stray or misspelled keys before upgrading.
 - The frontend projectSchema.json now requires entity_count in project metadata; project metadata
documents that do not provide it will fail schema validation.

### [PR #464](https://github.com/humlab-sead/sead_shape_shifter/pull/464)

- Sync the environment (uv sync) to install the new graphifyy[all] dev dependency and its
transitive packages.
 - Re-install pre-commit hooks: formatting is now handled by black + isort instead of ruff-format,
and the local check-imports hook has been removed.
 - .codex/hooks.json hard-codes a machine-local absolute path (/home/roger/.../.venv/bin/graphify
hook-check); other developers must adjust it to their own virtualenv location.

### [PR #466](https://github.com/humlab-sead/sead_shape_shifter/pull/466)

- The options.mapping section in shapeshifter.yml is deprecated and ignored during normalization (a
warning is logged). Existing entries must be moved to <project>-mapping.yml or recreated via the
new mapping endpoints; no automated migration is included in this PR.
 - Note the replace-on-save behavior: saving a materialized entity replaces all source: "manual"
sidecar links for that entity with the links extracted from the currently saved rows (reconciliation
and import links are preserved). Manual links intentionally absent from the saved rows will be
removed.

### [PR #467](https://github.com/humlab-sead/sead_shape_shifter/pull/467)

Code that imports the configuration package must be updated; the old names were removed in this PR:

 - ConfigFactory().load(...) → load_config(...) (from src.configuration or
src.configuration.config).
 - Config.resolve_references(...) / Config.find_unresolved_directives(...) → module functions
resolve_references(...) / find_unresolved_directives(...) from src.configuration or
src.configuration.resolve.
 - ConfigValue / inject_config / Configurable now live in src.configuration.config_value (still
re-exported from src.configuration).
 - src.configuration.interface is deleted; import ConfigLike from src.configuration.config (or
src.configuration). ConfigFactoryLike no longer exists.
 - src.configuration.setup (setup_config_store, get_connection) is deleted; callers must set up
configuration and connections by other means.
 - Backend: replace the Ingesters global with get_ingester_registry(), and call IngesterService
through get_ingester_service() instead of its former static methods.
 - Behaviour change to be aware of: @include: / @load: paths whose environment variables expand to a
relative path are now resolved relative to the env file's directory rather than the process working
directory.

### [PR #469](https://github.com/humlab-sead/sead_shape_shifter/pull/469)

- The default APPLICATION_ROOT changed from the installed package directory to the current working
directory. Deployments that relied on the old default should set SHAPE_SHIFTER_APPLICATION_ROOT
explicitly; relative SHAPE_SHIFTER_* path values are now resolved beneath it.
 - Prefer @load: over @include: for metadata.target_model in project files; the included model is
loaded raw without recursive directive resolution. Both prefixes remain accepted by the resolver.
 - Python callers importing TaskList/LayoutOptions from src.model must import from src.sidecars;
load_config/resolve_references/is_config_path usages should migrate to
load_resolved_yaml/resolve_directives/is_yaml_file.

### [PR #471](https://github.com/humlab-sead/sead_shape_shifter/pull/471)

No action is required to keep existing behavior: without the new optional mutable_fields_by_entity
configuration, existing rows continue to be planned as reference-only, and
existing_row_update_entities can optionally restrict which entities may take the first existing-row
update slice. Note one artifact change: rendered INSERT and \copy payloads now exclude system_id and
*__existing baseline columns, so any tooling that depended on those columns appearing in deploy SQL
or CSV sidecars needs updating.

### [PR #477](https://github.com/humlab-sead/sead_shape_shifter/pull/477)

- The submission context field issue_number is renamed to issue_identifier; API consumers and any
tooling that builds submission context payloads must use the new name.
 - Projects whose target model contains a submission entity must set metadata.data_provider_code;
missing or unknown codes are validation errors, and the ingester never allocates a provider.
 - Generated artifacts that emit submission rows require the upstream SEAD DDL (tbl_submissions,
tbl_data_providers, tbl_submission_states, and related tables, plus tbl_datasets.submission_id) to
be deployed before the change package can run. This upstream dependency is documented in the
proposal; the migration itself is out of scope for this repository.

### [PR #482](https://github.com/humlab-sead/sead_shape_shifter/pull/482)

- Target model files moved from target_models/ to resources/target_models/; update any paths that
reference the old location.
 - Relative data paths (projects/, logs/, shared/) are now resolved against APPLICATION_ROOT; set
SHAPE_SHIFTER_APPLICATION_ROOT or SHAPE_SHIFTER_ENV_FILE if you relied on the previous
working-directory-based resolution.
 - A new optional SHAPE_SHIFTER_SIMS_SERVICE_URL setting points to the authority service for
/identity endpoints; set it if you use the SIMS/change-request features.
 - Copilot prompt files moved from prompts/ to .github/prompts/; update any editor shortcuts or
links to the old paths.
